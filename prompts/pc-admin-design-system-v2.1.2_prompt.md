## 一、角色与目标

你是一名资深产品设计工程师。v2.1.1（卡 17–19，PR #139–#141）已合并，大结构正确，剩下的问题集中在精度：令牌取值、区块间距、少数状态的视觉语义，以及会话页和通知异常页没有跟上新的筛选样式。

本轮目标是**把每一处都做到和原型、规范完全一致，一次做完，不留返工**。为此：

1. 每个问题按「现象 → 位置 → 修改 → 验收」执行，不要只改样式不补验收。
2. 标有「先确认原因」的问题，必须**先补齐合成数据**让该场景在截图和测试中真实出现，再判断原因，最后修改。原因写进执行记录。

## 六、卡 20 · 令牌、间距、工作台与抽屉

### A. 令牌（`src/design/tokens.css`）

**T1 实心徽标颜色**
- 现象：会话未读数等实心徽标是深藏青，不像提醒。
- 原因：`--tone-*-solid` 全部等于对应的 `-fg` 深色。
- 修改：第 1 层新增 `--red-600: #C9332D;`。第 2 层改为 `--tone-brand-solid: var(--blue-600);`、`--tone-danger-solid: var(--red-600);`，其余 solid 保持不变。
- 验收：白字在两种底色上的对比度分别为 5.67:1 和 5.26:1（写入注释）；会话列表未读徽标显示为品牌蓝。

**T2 删除看板底板**
- 现象：三条泳道下面垫着一大块暖灰底板，双层背景发闷，且底板延伸到最长一列。
- 位置：`components/BoardColumn/workbench-board.css` 中 `.board {… background: var(--bg-board)}`；`board-column.css` 的 `.ds-page>.board {background: transparent}` 没有命中。
- 修改：删除 `.board` 的 background；删除 Token `--bg-board`、`--bg-column`，以及第 1 层只为它们存在的 `--gray-board`、`--gray-column`（先全局搜索确认没有其它引用）。
- 验收：浏览器断言 `.board` 计算后的 `background-color` 为透明；三条泳道直接位于白色页面上，各列底部高度自然不齐。

**T3 语义层不写裸 hex**
- 修改：把第 2 层里的 `--border-brand-subtle: #BFD3F2`、`--lane-intake/active/done` 的十六进制值移到第 1 层，命名为 `--blue-200: #BFD3F2`、`--yellow-25: #FCFAF4`、`--blue-25: #F6F9FE`、`--green-25: #F5FAF6`；第 2 层改为引用。全局搜索第 2 层中是否还有其它裸 hex，一并处理。
- 验收：第 2 层（语义 Token 区块）中不再出现 `#` 开头的色值；视觉无变化。

**T4 计数文字颜色**
- 现象：视图页签中的计数用了 `--text-tertiary`（白底 3.45:1），计数是必读信息，不达标。这是原型的错误。
- 修改：页签计数改为 `--text-secondary`（5.48:1）；「已超时」保持 danger 色。全局搜索其它用 `--text-tertiary` 显示数字或必读信息的地方（列头计数、卡片时间、表格时间等），一并改为 `--text-secondary`。`--text-tertiary` 只保留给占位符、禁用态和装饰图标。
- 验收：在 `docs/ui/design-system.md` 的颜色表中补一句「计数和时间属于必读信息，不得使用 tertiary」。

**T5 下一步卡文字层级**
- 现象：非等待状态下整张下一步卡的文字都是阶段色（例如整段蓝字），看起来像链接，层级扁平。
- 位置：`components/Drawer/drawer-v21.css` 中 `.ds-next-step {… color: var(--stage-intake-fg)}` 及 `[data-stage=active]`、`[data-stage=closed]` 的同类规则；`NextStep.tsx`。
- 修改：
  - 卡片背景保留阶段浅色，`color` 改为 `--text-primary`。
  - 左侧新增 34px 圆角图标块（与等待状态的时钟图标块同尺寸），内放该阶段的 `StageGlyph`，图标块底色为白色半透明。
  - 「下一步」小标题：`--fs-xs`、`--text-secondary`、500。说明句：`--fs-md`、`--text-primary`、600。补充说明（如跟进时间）：`--fs-xs`、`--text-secondary`。
  - 等待状态的现有样式保持不变，只确认与上面的层级一致。
- 验收：五种状态（待接单、已领取、处理中、等待中、已解决）各截一张抽屉图；任何状态下正文都不是彩色。

**T6 滚动条**
- 新增 Token：`--scrollbar-size: 8px; --scrollbar-thumb: var(--gray-300); --scrollbar-thumb-hover: var(--gray-400); --scrollbar-track: transparent;`
- 在 `base.css` 中统一定义：Firefox 用 `scrollbar-width: thin; scrollbar-color: var(--scrollbar-thumb) var(--scrollbar-track)`；Chromium / Electron 用 `::-webkit-scrollbar`（宽高 8px）、`::-webkit-scrollbar-thumb`（圆角全圆、2px 透明边框配合 `background-clip: content-box`）、`::-webkit-scrollbar-button {display: none}`，悬停时 thumb 用 hover 色。
- 验收：会话消息区、会话列表、抽屉内容区、看板横向滚动都不再出现系统默认的粗滚动条和上下箭头（在 Electron 或 Chromium 下截图）。

**T7 程序焦点不显示框**
- 现象：抽屉打开后标题被程序聚焦，出现蓝色矩形框。
- 位置：`WorkbenchDetail.tsx` 标题 `tabIndex={-1}`；全局 `:focus-visible` 规则作用到了它。
- 修改：`base.css` 增加 `[tabindex="-1"]:focus, [tabindex="-1"]:focus-visible {outline: none; box-shadow: none;}`。保留聚焦行为本身（读屏和键盘需要）。全局搜索其它 `tabIndex={-1}` 的程序焦点目标，确认都没有可见框。
- 验收：浏览器断言抽屉打开后 `document.activeElement` 是标题，且其计算后的 `outline-style` 为 none、`box-shadow` 为 none；按 Tab 移到下一个按钮时，按钮仍显示正常的键盘焦点环。

### C. 工作台

**K1 搜索占位文字**
- 位置：`features/search/WorkbenchSearch.tsx`。
- 修改：「搜索全部当前可读事项」改为「搜索工单号、标题、报修人」；同步测试期望。

**K2 搜索框旁的「⌄」**
- 现象：搜索框右侧外面有一个独立的「⌄」，含义不明。
- 修改：先在执行记录中说明它是什么。如果是搜索范围或高级搜索入口，把它收进搜索框内右侧，改为 16px ghost 图标按钮（如 `sliders-horizontal`），加 `aria-label` 和 tooltip「搜索选项」；如果没有实际功能，删除。

**K3 「我负责」页签没有数字（先确认原因）**
- 先补合成数据：在工作台 fixture 中，让当前测试账号负责 3 张未完成工单（处理中 2 张、已领取 1 张）；另准备一个负责 0 张的账号。
- 再确认：数据补齐后数字是否出现。可能的原因：fixture 中本来就没有指派给当前账号的工单；计数逻辑只统计了某一列；或者该账号属于「无法统计」。
- 修改：按 v2.1.1 规范处理三种情况：有数据显示数字；为 0 显示「0」；无法统计不显示数字但有 tooltip 说明原因。
- 验收：两个账号各截一张；补浏览器断言：负责 3 张的账号显示「3」，负责 0 张的账号显示「0」。

**K4 处理中列没有热度芯片（先确认原因）**
- 先补合成数据：在工作台 fixture 中加入以下工单，并写入真实的状态事件，使 `stage_entered_at` 有值：
  - 处理中，进入状态 3 分钟前 → 不显示热度
  - 处理中，12 分钟前 → 中性「12 分钟」
  - 处理中，45 分钟前 → 黄色「45 分钟」
  - 处理中，2 小时前 → 橙色「2 小时」+ 橙色描边
  - 等待厂商，5 小时前 → 红色「超时 5 小时」+ 红色描边
  - 待受理，创建于 26 小时前 → 「超时 1 天」
- 再确认：如果补数据后热度正常显示，原因就是 fixture 缺状态事件，无需改产品代码；如果仍不显示，检查 `Workbench.tsx` 中 `start=item.column==='pending'?item.created_at:item.stage_entered_at` 一行以及时间格式转换。
- 验收：截图中六种热度状态都可见；补浏览器断言覆盖这六张卡片的芯片文字和 `data-ring`。

**K5 多个筛选时的「清除」**
- 修改：当 ≥ 2 个筛选生效时，在最后一个筛选胶囊后显示 ghost 按钮「清除」，点击清除全部筛选（不清除视图页签和日期）。只有 1 个时不显示，用胶囊自己的 × 即可。
- 注意：只在工作台调用处加按钮，不改筛选胶囊组件本身（那是卡 21 的范围）。

**补充：类别图标的合成数据**
- 现象：截图里所有卡片都是「未分类」问号，类别图标的视觉效果从未被验证过。
- 先补合成数据：通过现有 H5 报修 fixture，用报修人显式选择的服务代码（`REPORTER_EXPLICIT`，ADR-0021 / ADR-0052 已支持）创建至少 4 张已分类工单，服务代码使用当前示例目录中存在的：`PRINT.PRINTER_DEVICE`（应显示打印机图标）、`NETWORK.ENDPOINT_ACCESS`、`DIAG.IMAGING_VIEWER`、`CLINICAL.INPATIENT_WORKSTATION`；保留 2 张未分类。
- 验收：截图中能看到 4 种类别图标与颜色；未分类为安静的灰底问号。

### D. 抽屉

**D1 标题蓝框**：见 T7。

**D2 状态未变化却显示「待接单 → 待接单」（先补数据）**

### B. 会话

**C1 列表项时间被截断、预览没有省略号（先补数据）**

- 验收：1280 和 1920 截图中，长名字的联系人时间完整显示；补浏览器断言：时间元素的右边缘不超出列表项的右边缘。

**C2 日期分隔线顺序（先确认原因）**
- 先补合成数据：同一联系人、同一主题下的消息覆盖两天，时间戳分别为「昨天 16:40、昨天 16:52、今天 09:10、今天 09:30」，其中第三条从群聊切到 Bot 私聊。
- 再确认：渲染顺序是否为时间升序。如果原 fixture 的消息时间戳本身就是乱序（例如「今天」的消息被写在「昨天」之前），说明是数据问题：修正原 fixture 的时间戳，并在执行记录中说明；如果补的新数据仍然乱序，就是排序问题：按消息时间升序排序。
- 规则：同一天只出现一次日期分隔线，放在当天第一条消息之前，格式「今天 / 昨天 / MM-DD」；渠道名只在渠道切换时出现在分隔线上，例如「今天 · 切换到 Bot 私聊」。
- 验收：补浏览器断言：分隔线文字依次为「昨天」「今天」；分隔线数量等于天数 + 渠道切换次数。

**C3 内部备注重复三次「内部」（先确认原因）**
