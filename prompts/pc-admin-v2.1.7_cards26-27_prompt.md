## 一、背景

- 当前代码事实（供 27A / 27B 核对，不要只信这里）：

### D1 气泡尖角没有生效

- **现象**：`message-bubble.css` 第 3–4 行已写「每组第一条，发送人一侧上角 4px」，但 `v215-card24/glyph-bubble-meta-x2.png` 中第一条气泡左上角仍是大圆角。
- **修改**：找出覆盖来源（会话样式里选择器更具体的 `border-radius`，或灰底画在子元素上）。保证**画出背景色的那个元素**拿到分组圆角。不要用 `!important`。
- **验收**：浏览器实测第一条 incoming 气泡背景元素 `border-top-left-radius = 4px`，其余三角 12px；第二条四角 12px；outgoing 对称。附 2 倍截图。

### D2 「0 分钟」改为「刚刚」

- **现象**：会话联系人列表等待不足 1 分钟显示「0 分钟」，工作台同类场景显示「刚刚」。
- **修改**：等待时长不足 1 分钟统一显示「刚刚」（颜色仍按热度规则）。先确认是 `heatOf` 还是会话侧的格式函数产生「0 分钟」，只改一处，两边共用。
- **验收**：单测覆盖 0 秒、59 秒、60 秒三个输入。

### D3 状态行省略为 0 的项

- **现象**：「待接待 · 1 个主题 · 0 个群」。
- **修改**：数量为 0 的「个主题 / 个群」不显示；「至少 N 个群」规则不变。
- **验收**：合成数据断言不出现「0 个」。

### D4 等待横幅的收缩顺序

- **现象**：1440 下显示「何明（合成）已等待 5 小时，尚无人…」，关键的「尚无人接待」被截断。
- **修改**：横幅文字拆为三段，空间不足时按以下顺序收缩：
  1. 先隐藏「 · 接待后即可回复」（用容器查询或 JS 测量均可，优先 CSS 容器查询）；
  2. 再截断姓名（姓名段 `min-width: 0; overflow: hidden; text-overflow: ellipsis`，最大 8em）；
  3. 「已等待 N，尚无人接待」始终完整，`white-space: nowrap; flex: none`。
- **验收**：1440 与 900 下断言「尚无人接待」元素 `scrollWidth <= clientWidth`；1920 下三段都可见。

### D5 「在抽屉中打开 ↗」左对齐

- **现象**：链接比上方关联事项卡片的左边缘多缩进约 8px（ghost 按钮的左内边距）。
- **修改**：该链接左内边距为 0（或用链接样式而不是 ghost 按钮），悬停背景向两侧外扩不影响文字对齐。
- **验收**：实测链接文字 `left` = 卡片 `left`（±1px）。

### D6 会话头部主题选择器宽度

- **现象**：主题选择器约 270px，把第二行「科室 · 渠道」挤成「群来…」。
- **修改**：主题选择器 `max-width: 240px`（与原型 03 一致）；第二行优先保留渠道（渠道名短），科室先省略：科室段 `min-width: 0` 可省略，渠道段 `flex: none`。
- **验收**：1440 下实测选择器宽度 ≤ 240px；第二行渠道文字完整。

### D7 看板合成数据补齐分类

- **现象**：卡 24 看板截图每张卡都是灰色「?」（未分类），无法验证分类色块。
- **修改**：在工作台看板 fixture 中，让合成工单的 `service` 覆盖至少 4 个业务域（例如打印、网络、临床系统、终端设备），并保留 1 张未分类。只改合成数据，不改分类映射。
- **验收**：1440 看板截图中可见至少 4 种分类色块。

### D8 泳道描边与原型对齐

- **现象**：泳道外有一圈 `outline: 1px solid var(--lane-border)`，在截图中比原型明显。原型 01 是 `box-shadow: inset 0 0 0 1px rgba(55,53,47,.05)`（内描边，5% 透明度）。
- **修改**：改为内描边，颜色取现有 Token 中最接近 5% 的一个（例如 `--border-hair` 为 9%，如果没有 5% 的 Token，在 `tokens.css` 新增 `--lane-border: rgba(55,53,47,.05)` 并说明理由）。
- **验收**：计算样式中无 `outline`，`box-shadow` 为 1px 内描边且透明度 0.05。

### B1 第三列分组（原型 01、01b）

- 第三列标题仍为「已处理」，计数 = `completed + dismissed`。
- 列内两个分组，样式与第一列「待判断 / 待接单」分组相同（12px / 500，`--text-secondary`，折叠箭头）：
  - **已完成 {n}**：默认展开；
  - **已关闭 {n}**：默认折叠；分组标题右侧 `--text-tertiary` 小字「不计入完成数」。
- 折叠状态按用户记忆（沿用现有 UI 偏好存储方式，如 `useUiStore`；没有则用会话级状态）。
