### K 关闭对话框（原型 01b、01d）

**K1 「非 IT 范围」的具体情况只保留 3 个**

- **现象**（`02-not-it.png`）：选「非 IT 范围」后列出了人工复核的全部 8 个原因：人工核对确认、描述不足需要补充、确认收到、待公共故障审核、明确取消旧复核等，这些都不是「为什么不属于 IT」，语义错误。
- **修改**：
  - 关闭对话框中「非 IT 范围」的二级原因只保留 3 个，沿用现有原因码、只改显示名：

    | 原因码 | 显示名 | 辅助说明（12px `--text-tertiary`） |
    | --- | --- | --- |
    | `BUSINESS_CONSULTATION_CONFIRMED` | 业务咨询 | 不是故障，只需解答 |
    | `OUT_OF_SCOPE_CONFIRMED` | 其他部门职责 | 后勤、设备、医务等 |
    | `SERVICE_REQUEST_CONFIRMED` | 服务请求 | 需走申请流程 |

  - 呈现为「非 IT 范围」下方缩进的子选项组（左缩进 26px，`--bg-subtle` 底，圆角 8，标题「具体情况 *」），子选项行高 32、13px；选中项白底 + 1px `--border-brand-subtle` 描边。
  - **后端例外**：关闭命令对 `NOT_IT_SCOPE` 的二级原因校验收紧为这 3 个码（只改关闭路径的校验与对应测试；人工复核工作区自身的 8 个原因保持不变）。
  - 关闭记录、卡片原因标签、列表原因中的二级原因同样使用新显示名（`closure-presentation.ts`）。
- **验收**：对话框只出现 3 个子选项；后端对其它 5 个码返回校验错误（测试）；原因标签显示「非 IT 范围 · 业务咨询」。

**K2 选项文字颜色**

- **现象**：「误报或测试」中的「测试」二字显示为橙色（`01-duplicate.png` 等）。
- **修改**：找出原因（疑似搜索高亮或文案组件着色），所有选项文字统一 `--text-primary`。
- **验收**：断言每个选项文字的计算颜色一致。

**K3 原单关联改为组合框**

- **现象**：现在是「输入框 +『按编号搜索』按钮 +『已关联 … 清除关联』」三行拼接。
- **修改**（原型 01d「关联原单 · 组合框」）：
  - 一个组合框：前缀 14px 搜索图标；输入即搜索（防抖 250ms，复用现有工单编号搜索能力）；下拉每行「20px 分类图块 + 编号（`--font-mono` 12px）+ 标题（单行省略）+ 阶段标签」，行高 40；
  - 选中后框内显示「工单图标 + 编号 + 标题（`--text-secondary`）+ 清除按钮（24px，`X`）」；
  - 只显示对外编号（`IT-…`），**不显示内部引用**；不能选自己；
  - 无结果时下拉显示「没有找到可关联的工单」。
- **验收**：键盘可操作（上下选择、Enter 确认、Esc 关闭）；选中后提交的是原单引用。

**K4 通知提示与终止提示分开**

- **现象**：通知提示块里同时写了「进行中的跟进与提醒将一并终止」；选「其他」时出现复选框「通知报修人」后又重复一行标题「将通知报修人」。
- **修改**：
  - 通知提示块只讲通知：「🔔 将通知报修人」+ 文案，或「不会通知报修人」。
  - 「其他」：提示块首行为复选框 +「通知报修人」；勾选后下面显示文案，不勾选时显示「不会通知报修人」；不再重复标题。
  - 「进行中的跟进与提醒将一并终止」移到提示块**外**，单独一行：13px `TriangleAlert` + 12px 文字，`--tone-attention-fg`；只在处理中、等待类状态关闭时出现。
  - 「关闭后不计入完成数…」这行删除（对话框已足够长，该信息在关闭后的提示条和已关闭分组里已有）。

**K5 底栏与孤立图标**

- **现象**：对话框底部有一个孤立的 ⓘ 图标和一行单独的「清空填写内容」。
- **修改**：底栏一行：左侧「✓ 草稿已保存 · 清空」（12px `--text-tertiary`，「清空」为 ghost 小按钮），右侧「取消」+「确认关闭」。没有草稿时左侧不显示。不得出现只有图标没有文字的状态。

**K6 对话框规格与 ⋯ 菜单**

- 关闭对话框：宽 440、圆角 14、内边距 20、标题 16 / 600；第二行编号 · 标题 13px `--text-secondary`；原因单选行高 36、选中行 `--tone-brand-subtle` 底。
- 抽屉 ⋯ 菜单（`01-duplicate.png` 右上）：现在是标题样式的「刷新可用操作」加一个按钮样式的「关闭事项」。改为标准菜单：宽 220、圆角 10、内边距 4；菜单项行高 32、14px 图标 + 13px 文字；「刷新可用操作」作为普通菜单项（`RefreshCw` 图标）；分隔线后「关闭事项…」为危险色菜单项（`CircleX`，`--tone-danger-fg`，悬停 `--tone-danger-bg`）。

### R 恢复确认（原型 01d）

**R1 文字重叠**

- **现象**（`04-restore-confirm.png`）：说明文字第二行与下方小字「已终止的跟进与提醒…」重叠。
- **修改**：修正行高与间距（检查是否有负 margin 或固定高度）；小字与正文之间 `--space-2`。
- **验收**：实测两段文字的矩形不相交。

**R2 结构与文案**

- 与关闭对话框同规格（宽 400、圆角 14、内边距 20、标题 16 / 600、右上关闭按钮）。
- 正文改为信息块（`--bg-subtle` 底、圆角 8、内边距 10 12），三行「标签 56px + 值」：
  - 回到：阶段标签（如「处理中」）；
  - 负责人：头像 20 + 姓名，或「未领取」；
  - 通知：三种文案之一——「关闭时未通知报修人，本次不发送」/「关闭时已通知，将通知报修人已重新受理」/「关闭通知尚未送达，恢复后将按送达结果决定是否通知」。
- 信息块下 12px `--text-tertiary`：「已终止的跟进与提醒不会自动重建，需要时请重新发起。」（只在关闭时确实终止过跟进时显示）。
- 去掉孤立的 ⓘ 图标。主按钮「↶ 确认恢复」。

### D 抽屉已关闭态（原型 01d）

**D1 状态徽标**：已关闭事项（`closure.kind = DISMISSED`）在抽屉标题下显示灰色「⊗ 已关闭」徽标，**不再显示绿色「已处理」**；后面的子状态「● 已取消」去掉。

**D2 下一步卡**：中性灰（`--bg-subtle` 底、1px 6% 内描边），左侧 28px 白底圆内 16px `CircleX`；第一行 12px「已关闭 · 不计入完成数」，第二行 14px / 600 原因（如「非 IT 范围 · 业务咨询」「重复报修 · IT-…」）；右侧 secondary「↶ 恢复」。**删除**信息区下方多出来的第二个「恢复」链接。

**D3 关闭记录紧凑化**：

- 按时间倒序，每次关闭一条：「头像 20 + **姓名** + 人工关闭 / 系统判定 · 时间」；下一行原因标签 + 原单链接（有才显示）+「已通知报修人」（有才显示）；说明（有才显示）为下方 `--bg-subtle` 小块。
- 恢复显示为该条记录下的一行 12px：「↶ 姓名 恢复 · 时间」。
- **值为空的字段不显示**（不再出现「未关联」「未记录」「未通知」）。
- 原单编号用 `--font-mono` 链接，点击打开原单抽屉。

**D4 提示条文案**：关闭成功：「已关闭」+「可在『已处理 · 已关闭』中恢复」；恢复成功：「已恢复」+「已回到{列名}」。**只在关闭和恢复流程中**替换掉「原操作已核对为提交…」这类技术化文案（该文案在其它功能中也出现，本卡不改，记录在执行记录中供后续统一）。

**D5 「已取消」统一显示为「已关闭」**：PC 端状态映射（`status-map.ts`）、动态记录（如「处理中 → 已取消」）、筛选与标签中，`CANCELLED` 的中文显示统一为「已关闭」。不改状态值。

### B 看板

**B1 重复原因标签**：已关闭卡片的「重复 · IT-…」中，编号放在同一个标签内（`--font-mono` 12px），去掉标签外的竖线分隔与放大的编号。

### L 列表视图（原型 01c）

**L1 报修人 · 位置的缺失处理**：只有一部分缺失时只显示存在的部分（不显示「— · 位置」）；两者都缺时才显示「—」。

**L2 负责人单行**：长姓名（如「阿卜杜拉艾合买提」）不得换行；单行省略，`title` 为全名；行高保持 44（实测）。

**L3 分组行背景**：「结束方式」筛选后第一组、以及列表底部的阶段分组行出现灰色底条；阶段分组行背景统一为白色（`--bg-canvas`），只有子分组行用 `--bg-subtle`。

**L4 「收起」按钮**：与「显示剩余 N 项」同样式，加 14px `ChevronUp` 图标。

**L5 原单显示内部引用（P1）**

- **现象**（`list-1440-dismissed.png`）：原因列显示「重复 · TKT…」，用的是内部引用而不是对外编号。
- **修改**：确认 `closure.duplicate_of` 是否提供对外编号。提供则前端改用；不提供则**后端例外**：在工作台卡片投影中补充 `duplicate_of.display_no`（只读，同 PR 更新契约与 PC 解析层）。看板、列表、抽屉三处都只显示对外编号。
- **验收**：三处断言显示 `IT-` 开头的编号。

**L6 搜索结果缺分类与时效**

- **现象**（`list-1440-search.png`）：搜索结果中分类全部为「?」，处理中事项时效为「—」，而非搜索时同一事项有分类和热度。
- **修改**：确认搜索结果的数据是否缺 `service`、`stage_entered_at`（或热度所需字段）。缺则**后端例外**：在工作台搜索结果投影中补充这些只读字段（与看板卡片一致），同 PR 更新契约与 PC 解析层；不缺则修前端映射。
- **验收**：同一事项在搜索与非搜索列表中的分类图块与时效一致（断言）。

**L7 清理遗留合成数据**：「旧记录缺少关闭证据（合成）」这类历史形态数据按 U7 删除，用新规则重新合成。
