## 一、背景与口径

- 原型 **01e 工作台 · 协作在场与在线同事**、**01 工作台**侧栏底部有「在线同事」：一排头像 + 人数，点击展开列表。卡 30 当时按 P3 没做，用户现在确认要做。
- 卡 30 的口径继续有效：单台服务器、进程内存、**性能有保障、实现要简单**、不新增依赖 / 存储 / 后台任务。

**本卡口径**：

| 编号 | 口径 |
| --- | --- |
| O1 在线的定义 | 当前账号**有至少一个打开的工作台实时连接（SSE）**即为在线。不新增任何登记、心跳或接口调用；直接用服务端已有的 SSE 连接集合判断。 |
| O2 掉线宽限 | 连接全部断开后**保留 15 秒**才视为离线（与租约时长一致），避免刷新页面或短暂断线时头像闪烁。宽限在读取时按时间判断，**不新增定时器**。 |
| O3 可见范围 | 只显示与当前账号**同团队、互相可见**的同事（以现有工作台团队成员 / 授权规则为准，先核对），**不显示自己**；只读账号也算同事并可见。 |
| O4 状态 | 每位同事的状态由卡 30 的在场数据得出：有任一编辑租约 →「正在编辑」；有任一查看租约 →「正在查看工单」；否则「在线」。**不显示具体是哪张工单**。 |
| O5 刷新 | 在线集合变化时，复用卡 30A 的在场版本号（+1），沿用同一个 `workbench.activity.changed` 提示和 1 秒节流；**不新增事件类型**。前端收到提示后与批量在场读取一起防抖刷新。 |

## 四、后端

### S1 先核对（写进执行记录）

1. SSE 模块里每个连接是否能拿到 principal 与显示名；连接打开 / 关闭的位置。
2. 现有「团队成员 / 互相可见」的判断函数在哪里（卡 30 的 `authority` 是按事项判断的；这里需要按人判断）。如果没有按人判断的现成函数，用「两人都属于同一个工作台团队且都启用了 activity」作为规则，在执行记录和 ADR 中写明；**不要**为此新增数据库表或字段。
3. 桌面端窗口最小化 / 隐藏时 SSE 是否保持连接（决定「在线」是否包含后台运行），只记录结论，不改行为。

### S2 在线列表

- SSE 模块对外提供只读函数：返回当前在线账号（有打开连接的），以及每个账号**最后一个连接关闭的时间**（用于 O2 宽限）。连接打开、最后一个连接关闭时调用 activity 模块提供的回调，使在场版本号 +1。
- 新增 `GET /api/workbench/online`（放在现有 activity HTTP 模块，复用鉴权、CSRF、开关与错误处理），响应：

  ```ts
  interface WorkbenchOnlineView {
    schema_version: 1;
    people: { display_name: string; status: 'EDITING' | 'VIEWING' | 'ONLINE' }[]; // 不含自己，最多 50 人
    total: number; // 可见在线同事总数（可能大于 people.length）
  }
  ```

- 排序：正在编辑 → 正在查看工单 → 在线；同类按显示名。
- 计算：遍历在线账号（上限为连接上限 64）→ 按 O3 过滤 → 用内存中的租约（上限 128）判断 O4 状态。单次计算是 O(连接数 + 租约数)，不调用逐事项鉴权。

### S3 契约与 ADR

- 更新 `contracts/workbench_activity_contracts.d.ts` 与 JSON Schema、`docs/api/*`；在 ADR-0057 追加「在线同事」：O1–O5、核对结论、最坏开销、隐私说明（只暴露同团队同事的显示名与粗粒度状态，不暴露工单）。

### S4 性能测量

| 指标 | 要求 |
| --- | --- |
| `GET /api/workbench/online`（64 个连接、128 条租约） | p95 < 10ms，无逐事项鉴权调用（计数断言） |
| 一个账号刷新页面（断开后 3 秒内重连） | 在线集合不发生变化，不触发提示 |
| 一个账号关闭全部连接 | 15 秒后从列表消失；期间不新增定时器（读取时判断） |

## 五、前端

### F1 侧栏底部「在线同事」行（原型 01e、01 侧栏）

- 位置：侧栏底部账号信息上方。
- 一行：12px `--text-secondary`「在线同事」+ 头像组 + 右侧人数（12px，`tabular-nums`）。
- 头像组：最多 3 个，20px，相邻重叠 5px，每个头像外 2px 侧栏底色间隔；右下角 7px 绿色在线点（`--tone-success-fg` 或最接近的现有 Token，外圈 1.5px 侧栏底色）；超出显示「+N」（11px）。正在编辑 / 查看的同事排在前面。
- 整行是按钮，悬停 `--bg-hover`，点击展开 F2 列表；`aria-label="在线同事 {N} 人"`。
- 0 人时显示「在线同事」+ `--text-tertiary`「暂无」，不可点击。
- 侧栏折叠时：只显示一个人形图标 + 右上角人数小圆点（`--tone-success-fg` 底、白字、11px），`title` 为「在线同事 {N} 人」。

### F2 在线同事列表（弹出层）

- 宽 260、圆角 10、内边距 6，阴影与其它弹出层一致；锚定在该行上方。
- 标题行「在线同事 · {N}」（12px `--text-secondary`）。
- 每行高 36：头像 22 + 姓名（13px）+ 右侧状态（12px）：正在编辑（`--tone-attention-fg`）、正在查看工单（`--brand`）、在线（`--text-secondary`）。
- 超过 50 人时底部显示「另有 {total − 50} 人在线」。
- 底部说明（12px `--text-tertiary`）：「只显示同团队、当前打开工作台的同事」。
- 键盘可操作（Enter 打开、Esc 关闭、焦点回到触发按钮）。不提供点击同事跳转等新功能。

### F3 刷新

- 首次进入工作台读取一次；收到 `workbench.activity.changed` 后与卡 30B 的批量在场读取**合并在同一个 1 秒防抖里**一起刷新（两个请求并行发出，不各自防抖）。
- 工作台不可见、离线、实时连接断开、`activity_enabled` 为假时：隐藏该行，不发请求；恢复后立即读取一次。
- 在线数据单独存放，只有侧栏这一行订阅，变化时不触发看板 / 列表重新渲染。
- 请求失败静默处理，保留上一次结果最多 30 秒后隐藏。

### F4 性能验收

- 60 秒内连续 30 次提示 → 在线列表请求 ≤ 30 次，且每次都与批量在场请求同一时刻发出（合并防抖生效）。
- 在线人数变化时，看板卡片组件渲染次数为 0（渲染计数断言）。
