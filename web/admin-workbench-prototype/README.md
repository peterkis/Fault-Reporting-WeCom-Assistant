# 管理端合成数据视觉原型

这是可丢弃的 UI 原型，用于回答：三列看板、紧凑列表、队列详情并排，哪种布局更符合小团队处理报修的习惯？A 是当前约定的默认布局，B/C 是结构对照，不修改已确定的业务规则。

## 运行

首次安装独立前端依赖：

```powershell
npm ci --prefix web/admin-workbench-prototype
```

在仓库根目录启动：

```powershell
npm run prototype:admin
```

打开 [原型 A](http://127.0.0.1:5193/workbench/prototype/?variant=A)。底部浮动条切换 [B 列表](http://127.0.0.1:5193/workbench/prototype/?variant=B) 和 [C 并排处理](http://127.0.0.1:5193/workbench/prototype/?variant=C)。焦点不在交互控件时，左右方向键也可切换；生产构建隐藏比较条。

构建检查：`npm run prototype:admin:build`。Vite 仅绑定本机 127.0.0.1:5193，原型是独立前端包，不更改业务服务路由或业务依赖。

## 可体验

- 团队工作/与我有关、内存搜索、需跟进筛选、今天/昨天与全部关闭记录切换。
- 卡片手柄跨列拖动、一次接单并开始、先领取、转派与责任链。
- 详情右侧宽面板、完整页面宽度切换、新建代录、关闭表单、重开原因。
- 内部过程与对外结果分别记录；非 Bot 来源不伪造自由聊天。
- 详情中的“模拟新补充”保留当前输入；旧回复不清除新到达的补充。
- 关闭表单中的“模拟同事并发接管”演示版本冲突及保留输入。
- 声音开关/试听；右上“演示控制”可重置数据、查看完整内存状态。
- 会话提供合成列表；公共故障及通知异常仅展示有限案例；知识库明确预留。

## 边界与已知简化

数据全部合成，刷新恢复初始状态，不使用 localStorage、数据库、真实成员目录、认证、业务 API、真实 SSE 或企业微信外发。在线头像、时长和通知成功是演示状态，不是现场证据。附件上传、完整公共故障操作、真实收件人详情及反馈入口未接入；重开通过管理端模拟。

目前重点是视觉和核心交互，不是全部业务动作实现。生产接入需补充成员授权范围验证、服务端复合命令、持久化阅读/跟进游标、断线恢复及完整权限等，不能直接部署原型。
