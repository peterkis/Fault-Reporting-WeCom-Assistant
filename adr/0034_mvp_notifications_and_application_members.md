# ADR-0034：MVP 群回应、完工通知与应用成员身份

状态：Accepted，依据用户于 2026-10-20 确认的实施计划。不是部署、扩大真实发送范围或 Gate 批准。

## 决策

- 群内 Bot 仅发送固定的故障受理确认、无法判断时的私聊引导、单纯致谢回复。其他明确非故障内容静默；留存、分类和人工复核继续执行。姓名仅作称呼，不冒充原生提及。
- 首报确认以已提交的受理／工单事实为依据；普通补充不重发，原消息重放不重复产生投递。致谢按本条消息判定，混合故障不当作纯致谢。
- 人工接管后的主题继续永久暂停规则，只有绑定原消息、纯致谢判定及固定模板的礼貌回复例外。例外不修改工单、不恢复其他规则。
- 每轮个人进度通知发生在首次实际接单／开始处理和工作人员完工。仅派单、转派、等待不通知。不改写首次责任事件。
- 群来源仅在工作人员完工后通过原群 Webhook 原生提及报修人，使用完整业务工单号；没有对应 Webhook 正常跳过，个人通知独立。群身份为原 botId + groupId，不使用群名称或最近沟通窗口。
- 个人卡片不展示渠道来源；已受理标题为“工程师正在处理你的工单”。内部来源及审计字段保留。
- 新 H5 身份模式使用本应用 OAuth 开放身份及当前可见成员核验，不以逐人名单作为新成员准入条件。开放身份和 Bot 原始 userid 分开建模；旧映射仅兼容原身份和记录，不重算历史绑定、不授予 PC 权限。
- 报修事务保存服务端核验的应用通知收件身份／命名空间／依据，沿既有 Web Request 绑定、Ticket Core 和 Outbox。登录会话不成为异步通知的收件事实源。当前成员资格于实际发送前独立核验。

## 合同与兼容

本决策前向调整 ADR-0006、0016、0023 中的群回应及通知节点，调整 ADR-0019 中新 H5 身份只能依赖有界名单的限制。原 Accepted 决策和历史 Evidence 保留其原时点；既有受限模式继续保持零外发和原身份语义。

既有 Message／Outbox 正文不修改。旧策略下未尝试且不适用的发送通过 Delivery 取消机制留审计；SENT 保持，UNKNOWN 沿原人工核对，不能因升级盲重发。新成员模式及迁移须显式选择，既有配置和持久开关默认值不变。

不建设新目录、全员同步、通用规则平台、第二工单核心或发送队列。新版 H5 UI 另行设计；本次只实现后端与接入说明。关闭新写入口和 Sender 后，保留原记录、本人读取及投递历史。

## 验证

群四类结果／混合致谢、重复与补充、接管后例外；派单无通知、每轮实际承接／完工、重开；多群与无 Webhook、分路恢复；H5 新成员／撤权／本人隔离／重启通知；等待后终检、内部备注隔离和 UNKNOWN 均须用隔离库及模拟外部边界验证。真实客户端 @ 和收件另留现场证据。
