# ADR-0029：正式管理端的前端与服务端状态边界

- 状态：Accepted（技术选型）；依据用户 2026-10-07 的明确决定，不是功能、现场或发布批准。

正式 PC 管理端复用已有 React/Vite/HeroUI/Tailwind/Lucide/Motion/dnd-kit，采用独立正式包及现有同源 HTTP/静态制品装配。新增 React Router 7、TanStack Query 5、Zustand、TanStack Table 和 Morphicons；首版浏览器为 Edge/Chrome。保留旧工作台、成员端及视觉原型，不引入 Next.js、BFF、ORM 或第二发布平台。

React Router 和 URL 承载可返回/刷新的导航；Query 承载获权服务端数据、分页和查询失效；Zustand 只承载共享界面状态及未来独立草稿；Table 承载列表呈现，不能把当前页筛选当全量查询。代价是新增少量锁定依赖，但避免后续工作区自行重建请求缓存、导航和表格引擎。工单、责任、关闭、沟通和可靠投递继续由原事实源及授权命令拥有；前端不复制第二状态机。

Morphicons 只增强状态切换的图标反馈，使用与 lucide-react 同版本的 lucide 数据，明确尊重用户减少动效偏好。WEB01 只读；写动作、刷新后草稿恢复、presence、未读/跟进、声音和桌面宿主分别留待对应后续切片。详细版本与契约见 [技术方案](../docs/ui/admin-workbench-architecture.md)。

2026-10-26 前向界面修正：按用户要求移除正式PC侧栏重复品牌、顶栏连接状态与旧管理端跳转，提醒偏好从侧栏设置进入。Query保留上次成功数据并利用结构共享更新变更字段；后台isFetching不能自行撤销已确认的呈现或反复切换控件可用状态，真正的401/403/404继续清理获权数据和输入，写入仍保留原版本/权限终检。Zustand仅增加设置面板开合状态。当前登录人员的姓名/部门通过原内部会话与已核实企业微信身份映射读取，显示资料不参与授予角色或处理组；报修人姓名/部门来自原报修资料，不用当前目录静默回写历史。

## 2026-11-01 v2.1 卡 8 顶栏修订

2026-11-01 v2.1 卡 8 前向修订：按用户本次明确要求，顶栏恢复只读连接状态并显示设置入口；人工协作 / 只读移入左下账号资料，所有一级页面显示面包屑。连接文字仅消费原 `RealtimeView.status`，不新增连接、请求、事实或业务就绪判断；原设置与退出能力保留。此项替代上文 2026-10-26 的“移除顶栏连接状态”展示决定，其余查询、资料、权限与 Gate 边界不变。

## 2026-10-27 详情展示补充

用户确认的 PC 详情原型允许详情可见区按需读取受控附件以生成缩略图；本补充替代该展示范围内先前不预取文件的限制。继续使用既有 T16 和网页报修媒体 Port、canonical READ、保留期限、完整性校验及同源 no-store 响应。读取串行；每项原始读取仍受既有 10/20 MiB 上限约束；浏览器只保留有界缩略图和一个主动播放/预览副本，离开详情、身份变化或可信 READ 撤销立即中止和撤销 URL。不持久化正文或媒体，不自动播放声音，不新增转写或扩展旧附件格式许可。

处理记录按北京时间逐日分组，长正文可折叠。被 CSS 截断、遮挡或不在前台的文本不得触发个人已读；展开后仍按原 READ 终检和完整可见范围确认。完工弹窗与常显备注只调整呈现，原写入权限、版本、轮次、明确确认、幂等身份和 UNKNOWN 恢复合同不变。

旧附件能力开启时，正式详情 HTML 的 CSP 仅增加 `img-src` 的 `blob:`，允许已校验原件生成的内存缩略图；音视频的 `blob:` 仍由 H5 媒体能力单独启用。脚本、样式、对象和框架限制保持。附件元数据、缩略图、主动预览及下载在同一页面顺序读取，普通点击等待当前读取结束；离开详情和权限撤销立即中断。

## 2026-10-27 消息反馈补充

依据用户指定，正式 PC 工作台采用锁定版本的 react-hot-toast 作为默认操作消息机制。使用其官方 headless 生命周期接口和项目静态样式，保留现有 CSP，不引入运行时样式注入。成功、失败、冲突及操作进度浮层展示，不挤动业务布局；重复状态更新同一条消息，离开所属界面或身份撤销清除对应消息。

消息只反映既有命令和查询的实际状态，不拥有业务事实，不自动发起、重试或重放命令。关闭提示不清理原 UUID、草稿或 UNKNOWN 栅栏；核对/恢复按钮、字段校验、明确确认和无法继续操作的必要状态继续留在所属位置。常态草稿保存使用安静的状态标记，恢复异常才产生消息；通知送达、处理记录和在线人员属于事实，不改成短暂 Toast。原生模态框内的提示继续可见和可操作，保持焦点与键盘访问。

## 2026-10-28 HeroUI 控件统一

按用户明确要求，正式 PC 管理端的交互控件统一使用现有 HeroUI v3，参考已配置的 HeroUI MCP 组件文档。按钮、输入、选择、确认、表单、折叠、表格及弹层保持既有业务控制器；弹层挂载不拥有草稿、原操作身份或结果核对状态。Toast 继续使用前述 react-hot-toast，挂入当前可访问的 HeroUI 弹层。HTML 语义结构及音视频、图片原生媒体能力保留。

工作台将已关闭分栏的展示名称改为“已处理”，不改 Ticket 状态或查询事实。移除旧范围下拉菜单，普通看板通过日期范围控件选择单日或起止日期；日期只限制已处理分栏，清除日期显示全部已处理记录。搜索继续遵循原搜索合同，不显示不受支持的日期控件。旧取消筛选链接须明确显示当前筛选，并允许清除。处理记录增加姓名前的细连接线和适当行距，内部标签只显示文字。


## 2026-11-04 绿色旧版工作台退役

用户明确以正式新PC管理端现有流程为唯一界面，不要求迁移或复刻旧页独有业务流。本前向决定替代首段“保留旧工作台”的现行要求；成员端、独立合成原型、离线正式画布与历史Evidence继续保留，不改写旧对象的验证结论。

退役web/p2-workbench页面/JS/CSS及专属预览、静态资源装配。正式PC宿主的/workbench（含尾斜杠）与/workbench/lifecycle以302/no-store转到/workbench/app/；/workbench/incidents转到/workbench/app/incidents/candidates。旧/static/workbench资源404，裸G1等没有正式PC的宿主不重定向到不存在的页面。原认证、回调/退出及原回跳白名单继续服务入口跳转，不提供旧HTML或旧业务流。

现行导航改用已有新PC入口；缺少对应功能的旧专属入口及处置承诺删除，不为退役补新流程。共享HTTP、现有域查询/命令、当前READ、原UUID与UNKNOWN恢复及已存在的新PC能力不删除。旧DOM测试按逐项处置退役，仍有效的后端权限、版本、恢复、隐私和发送断言保留在当前HTTP/新PC覆盖；历史来源、别名原命令和冻结checkout证据保持其原对象。范围与结果见[退役执行记录](../plans/pc-admin-design-v21/legacy-workbench-retirement.md)及[Issue #145](https://github.com/peterkis/Fault-Reporting-WeCom-Assistant/issues/145)。不推进部署、现场、真实发送、full/certify或Gate。
