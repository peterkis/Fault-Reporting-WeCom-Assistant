# ADR-0023：按报修原始来源路由工单状态通知

状态：Accepted for domain design，依据用户于 2026-09-22 明确的业务要求；不是运行实现、真实发送或部署批准。

工单通知按原始报修来源选择发送路径：Bot 单聊报修通过 Bot 私聊原报修人；医小修 H5 报修通过医小修企业应用发送模板状态消息；群聊 @Bot 报修通过企业微信“消息推送”在来源群强 @ 原报修人，同时由 Bot 私聊通知。群转单聊保留其原始群来源，后续访问 H5 或变更沟通窗口不自动改变路由。

用户进一步明确：Bot 在群内收到 @ 自己的报修消息后，私聊回复报修用户，不在群内回复。群内强 @ 是“消息推送”的职责，由 WeComMessagePushAdapter 独立承接；Bot 私聊回复与通知由各自 Bot 适配器承接。群推送不得回落为 Bot 群内回复。

选择该策略是为了让进展通知延续报修入口的沟通关系。相较全部使用应用通知，它减少 Bot 用户跨应用接收的割裂；相较仅私聊，群来源保留可见进展，同时承担群消息数量和内容最小化约束。群内只包含批准的低敏感进展摘要。

群通知和私聊形成两条独立 Delivery，各自幂等、记录结果并恢复失败，不把一条成功视为全部成功。采用消息推送实现强 @ 是用户明确的能力选择；本次未执行项目接入/现场验收，普通文本中的 @姓名 不构成强 @ 效果验收依据。具体 API 参数和配置在实施时核对。

本决策调整 ADR-0006/0016 中群来源工单状态通知的目标路由及 Bot 群内回执方向：Bot 回复统一走私聊、群强 @ 由消息推送承担，以及 ADR-0021 中 H5 APP_ONLY 的后续目标：H5 将在获准的业务通知模式中具备应用外发。保留身份/权限、原始来源真实性、隐私、Outbox/Delivery 和所有既有受限运行模式的零外发边界。当前代码和运行配置不因本 ADR 自动变化；实施任务必须同步契约、基线和验证。

通知节点沿用当前设计中的派单或自行承接、解决、重开后再次派工。关闭确认、超时关闭和额外节点仍按各自的产品定稿处理，本次来源路由决定不替代那些决定。

详细路由、去重与失败场景见 [领域设计第 8 节](../docs/domain-modeling/domain-design.md#8-通知是一条独立可靠链)。
