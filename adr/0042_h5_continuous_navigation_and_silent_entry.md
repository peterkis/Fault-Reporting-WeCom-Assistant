# ADR-0042：H5 连续页面展示与静默首次认证

- 状态：Accepted for implementation，依据用户 2026-10-22 部署后测试反馈及重构要求。
- 前向修订：ADR-0037 的首次认证展示与缓存展示、ADR-0041 第 6 项加载反馈；其余身份、命令、资源和预算合同保留。

已部署制品的实际浏览器反例显示，页面读取等待和首次 React lazy 提交分别挂载 Loading：260ms 读取出现两次骨架，25ms 对照仍出现一次。首次 401 的自动 OAuth 也先绘制了重连页。用户明确要求取消骨架，以下以此要求解释引用讨论中的冷启动策略。

1. 移除产品中的骨架组件与 shimmer。冷启动保持同主题的空应用背景，200ms 内完成不显示加载反馈；超过 200ms 显示 2px 顶部进度条。进度条一旦出现至少保留 300ms，再结束动效；最短时间只控制进度条，内容就绪立即可用，不为展示加载状态延迟内容。连续等待复用同一进度条，遵循 reduced-motion 和屏幕阅读器语义。
2. 路由目标和已展示页面分开。React Router 仍管理 URL、匹配、前进后退和链接；entry 与页面代码继续并行。目标未就绪时保留当前视图和布局，目标就绪后用 React 的延迟展示跨越 lazy 边界；仅挂载当前视图，不保留一组隐藏页面。列表筛选控件跟随目标 URL，原行保留到新 entry 就绪，避免连续筛选丢失已选择条件；等待期间不另起相同列表读取。切换和复核期间写操作关闭，导航保持可用。
3. 30 秒内的完整、新鲜、同成员范围与组织修订缓存保留原直接复用规则。30 秒至 2 分钟内的完整旧缓存可先展示，同时后台执行原 entry 复核；旧缓存不授予写权限。显式失效、被回收或不完整的数据不可作为目标页缓存；不得持久化成员资料、草稿或媒体。401／403、范围或组织修订变化立即清除旧展示、缓存、媒体和相关请求，延迟展示不能保留旧权限内容。
4. 正常企业微信首次进入或会话到期时，单次自动 `snsapi_base` 流程使用相同的轻量加载反馈，不先展示“Let's reconnect”或要求用户点重连。OAuth 仍经既有服务端入口、站内 return path、state/code 和终检，不声称跨域认证没有文档跳转。已有草稿／进行中或 UNKNOWN 命令时仍禁止自动离开，保留主动确认及跳转前再次检查；绝不自动重放 POST。
5. 自动认证返回仍失败时停止循环，显示可理解的失败与主动重试入口；403 保留权限提示，503／网络错误保留重试。外部浏览器直接提示“请在企业微信中打开”，不主动导航到官方授权域，也不输出 Provider 原始错误。UA 仅用于选择体验，不是授权凭据；所有服务端认证与 READ／写权限不变。本地显式 DEV preview 保持合成预览能力。

验证覆盖首次 401／授权返回失败／外部浏览器、草稿和 UNKNOWN 阻止自动跳转、快慢与临界延迟、缓存回访、筛选／详情／前进后退、连续切换、撤权及范围变更。实际生产构建、原 120KiB 首屏预算、相关注册测试、浏览器及资源清理分别记录；真实企业微信 OAuth 和设备体验由用户复验，不以合成结果替代。无数据库、持久 Feature Flag 或部署配置变更；回退沿上一验证制品，历史证据保留。
