# ADR-0036：医小修 H5 页面读取与媒体资源预算

状态：Accepted for local implementation。依据用户于 2026-10-20 明确批准并要求实施的 H5 前后端性能计划；不构成部署、现场写库、真实发送或 Gate 批准。

## 决策

保留 ADR-0035 的 Vite SPA、双主题双语言、原型基线、同源成员身份、CSRF、原 UUID 幂等恢复和 Unified Ticket Core。新增独立闭合的页面引导读合同，按当前页面合并 bootstrap 与最小业务页；原 V1/V2 DTO 和 HTTP 继续兼容。服务端直接复用获权查询 Port，不通过 HTTP 自调用，不复制 Ticket 事实。

每次 HTTP 请求只进行一次实际 Provider 资格核验；所有组成部分仍执行对应 READ、本人绑定及留存检查，依赖等待后和输出前继续终检。使用短 READ COMMITTED 事务；组织关系终检以新的语句观察当前关系。详情时间线仅在明确的 250 ms SQL 超时下用保存点降级为 UNAVAILABLE；授权拒绝与未知故障不得伪装成空数据。新页面详情补充及时间线各20条，首页3条，本人/科室页20条，签名游标保留范围与迟到事件语义。

浏览器在路由模块加载同时启动页面引导请求，确认 recovery_scope 后再填 Query 缓存。刷新入口集中并合并250ms内事件；业务数据30秒新鲜度、非活动缓存2分钟，不持久化敏感资料。缓存时效不授予权限。合法写回执先确认 committed，页面同步独立；UNKNOWN 继续保留原UUID和原用途，关键版本刷新前关闭相关后续写操作。

2026-10-21用户明确要求继续完成整页首页SELECT与大库并发预算。首页entry的集合SQL同时取得本人最近3条和当前获权科室真实统计，闭合DTO的`home.data.department_summary`为必填对象或null：有当前科室READ时返回真实统计及同一membership_revision，无权限时只返回null；读取失败不伪装为null或0。开始成员投影、集合读取、等待后的新语句组织关系与READ终检保留，整页首页业务SELECT上限仍为3。前端在确认范围后同时播种两份缓存，冷启动和统一刷新不再额外请求department-summary；该独立接口与旧V1/V2兼容路径继续保留。

同一用户授权要求专门记录2CPU/4GiB限制下的大库并发，不以旧小库结果替代。在Windows本地可采用任务自有Job Object，以挂起创建后分配作业再恢复的方式限制全部PG/App/Worker后代，使用2个允许逻辑CPU的affinity、CPU hard cap和4GiB作业提交内存上限，无breakaway、关闭作业回收。必须保存限制查询、CPU/内存越界反例、作业成员/峰值和清理记录；Windows提交内存与RSS、Linux cgroup的口径分别报告。此本地测试约束不修改生产资源配置或放宽指标；企业微信实机继续NOT_RUN。

同日受限大库对照证明逐行物理时钟SQL包装存在可消除的调用成本。允许仅在`src/yxx-h5-v2-profile.mts`的`departmentReportsSql`、`departmentInTransaction`两个热SQL构造器展开[ARCH-005规定的完全限定物理毫秒公式](../docs/48_arch_005_asia_shanghai_time_contract.md#h5-department-read-adapter-2026-10-21)。每处原guard仍独立调用真实时钟，不缓存、合并或替换为事务/语句时间，所有来源、当前关系、留存和等待后READ终检保持；022与全局helper、其他路径不改。采用前后保存同库同限制EXPLAIN及全DTO等价、真实到期/等待/时区/search_path反例；原helper替换探针不能冒充展开路径验证。回退只还原两处构造器的helper表达式，不新增Schema迁移、不改历史Evidence。2C4G与HTTP p95≤1.5秒等原指标保持，单SQL变快不代表并发验收通过。

受限探针06的实际执行计划证实4MiB work_mem下存在多批哈希落盘。允许H5首页统计/科室集合读取在同一短事务中，按顺序显式`SET LOCAL work_mem='16MB'`、`SET LOCAL hash_mem_multiplier=2`、`SET LOCAL max_parallel_workers_per_gather=0`，再执行原获权查询；正式路径与验收使用同一编译实现，不通过压测环境变量调大实例设置。16MiB是每个排序/物化操作的工作预算，单哈希可至32MiB，不是整条查询或进程上限；按并发会话、实际哈希/排序/物化节点计入总量，并保存全部作业成员commit/working-set实测。实例4MiB、原连接池、全树2CPU/4GiB硬限制及所有延迟指标不变。正常提交、异常回滚和同池连接复用必须证明恢复原设置。

同一探针允许将Ticket窄投影作为集合连接边界，消除十万次Ticket主键回查；科室列表可先物化已获权的两个来源UUID，减少后续哈希载荷。所有企业/应用/成员/组织、binding撤销及逐处留存条件仍在来源投影执行，过滤、稳定排序、签名游标、空页非零总数与末尾当前READ复核不变；不缓存统计、不复制事实、不添加未经计划证明的索引。该有限调优需由最终600正式大库请求与资源证明验收，组件探针不得标为最终通过。

### 2026-10-21：有限封闭在途批次的共同读取

正式候选03的600条HTTP测量中，Home／Department的p95分别为5.225／5.898秒，尚未通过原1.5秒预算。逐查询结构、覆盖索引、精确时间比较及减小活动SQL数的受限对照均不足以闭环；私有探针08在相同2CPU／4GiB和pool4下，十成员共同封闭SQL约0.29–0.33秒，逐成员完整原始DTO和企业／应用隔离等价。依据用户要求继续优化数据库瓶颈，允许以下有限共同执行；私有探针本身不构成HTTP验收通过。

仅性能开关已开启的Home科室统计与无筛选Department首屏可进入本实例的有界在途调度。每个HTTP仍独立完成Provider与对应READ admission、初始profile投影，并释放初始事务后才入队；排队不持连接、事务或锁。空闲时立即封闭并派发当前成员，不设置凑满人数的收集延迟。SQL派发后到来的任何请求只能进入下一批；已开始或已完成结果绝不供新请求附着、缓存或复用。其他视图、筛选、游标、独立统计和V1／V2继续原读取路径。

每个slot在共同SQL中按当前目录binding、账号、快照及部门关系重新取得自己的完整eligible集合，且与本人的初始membership证明一致。仅精确集合、source／corp／app、目录新鲜度策略及读取形状完全相同才共享来源扫描；不以部门编号、数组长度或摘要相等代替精确集合比较。本人最近3条、bootstrap、CSRF、recovery_scope、身份／写能力及游标签名始终逐HTTP独立；内部授权集合和分组映射不下发浏览器。已知失权只拒绝对应成员，未知SQL故障、错误映射和超限必须明确失败，不伪造null、0或空成功。

此为新的封闭批次共同语句快照：不同来源guard仍分别调用完全限定的原物理毫秒公式，不存储／共享clock值，不改022、全局helper或时间错误域；同一获权关系跨HTTP的重复扫描及guard物理求值次数会合并，不能宣称原逐HTTP调用次数不变。本段仅前向限定上述共同执行，原独立查询的guard边界不变。共同事务使用READ COMMITTED及原16MiB／hash2／parallel0设置。共同读取释放连接后，每个存活HTTP仍以自己的新语句复核当前profile／组织关系，并保留外层会话、scope、proof、session、flags及READ终检；成员变化不能由代表成员复核代替。

为使独立路径与批次不维护两份来源规则，将原profile内两个SQL构造器的闭合片段移入`src/yxx-h5-batch-sql.mts`的具名directory／reports／page构造器，以静态映射选择单请求参数或本次SQL内已核验slot／group字段。物理公式展开例外随这些相同片段前移；不允许运行时切片／正则解析SQL，不扩展至其他业务查询或全局helper。本人recent片段同样在静态构造器复用，原排序、高水位、BOT／WEB归属与安全字段保持。

每实例最多一个活动SQL批次，每批最多10个slot；排队、封闭、SQL完成后仍在终检／交付的slot合计最多20，FIFO服务。编码输入合计最多256KiB，驻留原始结果的编码预算合计最多4MiB；此预算不等于V8堆或进程RSS，实际全树资源仍独立测量。从已验证entry路由、独立Provider／成员核验前开始记录5秒单调时钟交付截止，覆盖核验、初始profile、队列、池等待、SQL和终检；直接查询Port调用在其入口兜底记录，不延长原池等待或1.5秒验收预算。SQL按剩余时间设置事务局部超时。超额429，超时503。只用原池，不新增服务、池、常驻轮询或持久事实。

20人的容量从初始profile获准执行时即预留，SQL或迟到checkout尚未结束的native工作继续占用，直到其实际settle才归还；不能只在enqueue检查或响应Promise结束就让新请求滚动填满。原池必须已有正值且不超过5秒的checkout截止，无界池拒绝装配此路径；不为压测改实例或扩大池。本地实际App入口为2秒、受限合成夹具为原5秒，分别记账，不将两者称为相同配置。

排队取消立即移除，已派发的单成员取消只丢弃其交付，不能中止其他成员的查询。全部成员取消后停止交付，已开始的SQL仍持有本次连接及活动槽，在原服务端statement_timeout内有限排空，等待真实成功／服务器错误响应及COMMIT／ROLLBACK清理后再释放；共享SQL采用封闭成员最晚截止，各HTTP仍按自己的截止停止交付。未开始SQL的迟到checkout直接销毁／释放。不能将Promise.race或本地socket关闭当作服务器SQL已结束的证明，也不为取消另建池或连接。各slot的容量lease保留到自身外层READ与交付结束及关联native工作实际settle；失败／取消／停止均一次释放监听、timer、原始结果和连接。取消后的有限排空单独测量，不声称交付截止即所有资源已经关闭；关闭入口须等待全部自有工作排空。

计量必须双账：m人成批时，逐人初始及末尾SELECT加一个共同SELECT，真实物理量为2m+1，每HTTP明确参与三个读取阶段。无共享的合法分支按实际计数；Home／Department上限仍≤3，request仍沿原≤6。记录唯一SQL执行ID、封闭参与者、各人直接／共享引用以及实际队列、池、SQL、终检时间；共享语句物理量只计一次，每参与者均有依赖引用，不分摊小数、不只计给首HTTP、不从HTTP耗时扣掉共享等待。内部稳定AsyncLocalStorage只在批次DB执行区提供只读关联信息，不含token、Cookie或业务正文，终检恢复各HTTP上下文。

采纳后重新编译、冻结新身份，验证无迟到附着、精确集合与企业／应用隔离、每人独立终检、取消／超限／超时／迟到连接清理、事务设置恢复和双账一致，再重跑完整600＋90及浏览器验收。原失败、2C4G／pool预算、1.5秒和实机NOT_RUN均保留；关闭性能开关沿原接口回退，不删除事实、派生文件或历史证据。

### 前端和媒体预算

主题/语言使用独立同源哈希小脚本在首次绘制前设置，主脚本不整体阻塞绘制。HTML与私有数据继续no-store；经过白名单与路径核验的公开内容哈希资源可immutable缓存，gzip/Brotli表示进入制品哈希。静态资源缓存最多4MiB，不缓存任何业务响应、身份结论或私有媒体。

五种固定Hash路径由本地类型化导航与页面引导共用描述，保留前进后退、筛选、直达及原生链接语义，避免再加载重复路由运行层。语义CSS类使用clsx；按钮与链接通过明确Button／ButtonLink组合，Dialog的Radix依赖只随弹窗加载。写入XHR与旧接口兼容实现按需导入，在导入等待前后校验原成员epoch与取消信号。此调整不改变管理端路由或根锁定依赖。

媒体新增私有AES-256-GCM THUMBNAIL派生副本，最长边960px且最多160KiB，由原Worker有限周期生成并按原件最早留存截止清理。原件字节和哈希不变。原生音视频读取可使用HEAD和单Range；每次请求与每64KiB输出块前保留当前READ、绑定和留存复核，完整GCM标签与SHA校验成功前不输出明文。播放副本最长边720px、24fps，视频最多8MiB，原件仍可获权读取。

前向替代原媒体整响应单活动槽：每个既有运行实例内，磁盘/加解密工作单并发，HTTP读取租约最多2个，活动明文及在途输出缓冲预留合计最多32MiB，等待项合计最多8个；任务60秒截止包含排队，排队后重新核验。App 与 Worker 各自管理本进程预算，不宣称跨进程共享32MiB：性能路径Worker单任务预留28MiB（20MiB原件加8MiB播放副本），与App最多合计60MiB；回退路径Worker最多32MiB，二者合计64MiB。该计数是受控媒体缓冲预算，进程RSS、FFmpeg内存与实际2C4G限制另行测量。上传仍串行；Worker转码单并发、单线程、25秒截止。不新增服务、常驻定时循环或数据库池，2C4G其他并发预算保持。

### 2026-10-21：性能 entry 的当前成员核验调度

正式06完整690请求证明Home／Department仍为1.624／1.674秒p95；SQL与独立终检均保留，初末池等待不足0.5ms，真实入队前跨度约1.1秒。该跨度不冒充尚未独测的Provider队列。私有09中Home直接聚合及完整授权条件的UUID residual有稳定收益，Department窗口方案无稳定收益，后者不采用。原Provider串行且小批反复扫描已成为需验证的组合瓶颈，允许以下仅性能entry的前向调度，不改1.5秒目标、数据库池或2CPU／4GiB。

只在APP且H5及性能开关均显式true时，启用同一当前成员verifier内的受信H5_ENTRY入口。原BASE入口实际并发仍最多1；H5_ENTRY最多2，二者共享APP合计最多2个实际在途和32项总容量（活动、等待及底层未settle操作均计入）。不是独立叠加两个32项队列。默认未开启时仍为原1／32。Gateway／Bot与发送使用BASE，不从客户端header、所有GET或未经验证的URL选择H5入口；不新增常驻服务、数据库池、资格缓存或实际Provider调用合并。既有应用access token Provider可继续按原合同复用，不能缓存成员仍有资格的结论。

两个入口在各自目的内FIFO，以最早可执行项填充共享槽，BASE活动上限1仍成立；不能因其一正在活动而无限阻塞另一目的的空闲槽。每项原5秒截止从入队开始，包含等待、token与网络。排队取消不发起Provider；活动超时／取消只停止交付，忽略AbortSignal的底层操作继续占用真实活动及总容量至实际settle，不能用Promise.race归还槽或滚动累积请求。失败不自动重试、不授权、不返回空成员成功。该有界只读核验是原Integration默认单并发的明确H5窄例外，真实发送与业务集成并发规则不变。

Native仅在已验证GET、无正文、同源、entry参数、READ与功能装配后选择H5_ENTRY。该入口、后续普通Query授权共用同一请求内pending Promise、prepared上下文及当前OAuth／Cookie／范围复核。每HTTP实际核验一次，不同HTTP即使同一userid也各自核验；不能新建第二认证实例或在Query重复Provider。等待后的profile／组织关系、外层READ及媒体终检全部保留，entry原绝对5秒时钟仍从独立核验之前开始。

仅诊断用途可记录无成员身份的opaque操作ID、目的、单调入队／实际开始／真实settle时刻与有界计数；无token、Cookie、userid或DTO。Provider队列必须由上述实际边界独测，不能由HTTP残差推算。验证默认／BASE单并发、H5双并发且共享2／32、33拒绝、排队与活动取消、迟到结束、失败隔离、合法路由选择和同HTTP只核验一次；随后按真实产品装配、同一编译身份重跑注册、完整690及浏览器验收。旧06 FAIL与Provider queue NOT_RUN原件保留，私有或新能力完成不代替HTTP达标。

## 关闭与验证

新路径沿原显式默认关闭H5装配；只增加前向迁移，不改变旧事实、历史Evidence或其他flags。回退页面/读取路径时保留派生对象到期清理能力。性能预算通过编译制品、任务自有loopback PG18、模拟Provider与浏览器测量；失败、NOT_RUN与实机缺口分别保留。验收过程及关闭方式见[实施记录](../plans/yixiaoxiu-h5-performance/README.md)。
