# ADR-0043：通知原链接统一进入新 H5，退役旧成员页面

- 状态：Accepted；依据用户 2026-10-22／23 明确要求和对机器人／代录详情承接范围的确认。
- 本次仅本地实现与验证；不授予部署、现场写库、真实发送或 Gate 批准。

原机器人卡片、经核实代录 App 通知和新 H5 的机器人记录仍使用 `/wecom/yixiaoxiu/tickets/{publicRef}`，其本人 READ 与 Web requestRef 自助权限不同。保留这些原链接、原 OAuth／归属终检、只读安全投影和独立 Bot 未解决反馈合同，由现有 React H5 制品统一呈现；不得把 publicRef 当成 requestRef 或以 MY_REPORTS 权限替代原 Reporter READ。代录原报修人可以读取原获权详情，不因页面统一获得 Bot 反馈资格。

`/reporter/open#grant=...` 的显式旧卡片策略继续沿原 Grant／绑定会话或成员转换链处理；fragment 立即清除，不落存储或日志。新页面同样遵守 5 秒单在途 GET、隐藏暂停、ETag 与时间线完整提交、失权清屏、明确退出和迟到结果 fence。Bot 反馈沿原版本／轮次／UUID／CSRF、独立目的回执及加密恢复，UNKNOWN 只由用户核对原操作，不自动重发。

旧 `web/p2-reporter` 的两套 HTML／CSS／JS 从活动源码和静态服务清单移除。新自助 H5 未显式装配时，原 V1 API 及业务开关保持；页面返回明确不可用，不回退旧界面或自动开启 V2 业务。Reporter 详情只加载新 H5 的展示及既有 Reporter 接口，不启动 Web 成员自助 Runtime。前端分包与有界静态验证复用现有预算，不新增常驻进程、数据库迁移或外部依赖。

需要保留的旧自助浏览器合同样本只作为显式测试夹具，不能被生产 handler 或新 H5 制品引用；这些历史回归不冒充新页面验收。新页面须独立验证原卡片、机器人本人反馈、代录只读、他人拒绝、退出、结果未知及原件隔离，替代完整后再删除旧活动资源。历史 Evidence、冻结合同、tested_head 和已记录失败保留。

迁移后的 PC 与 H5 生产源码和构建控制须同时纳入统一构建身份及既有候选指纹，防止源码移出 `web` 后脱离审批绑定。新增目录对历史根是可选输入，不纳入 node_modules、私有环境、设计原件或开发预览；没有这些目录的旧根保持原指纹内容。此路径补线不提高清单上限，也不改变 readiness、角色或任何 Gate 批准条件。
