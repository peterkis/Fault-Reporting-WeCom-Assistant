# ADR-0048: 工单人员资料采集、补全与随工单保留

Status: Accepted for the user-authorized defect repair on 2026-10-26. 用户明确要求来源、姓名、部门在工单完结后仍随工单持续保存；不推进任何后续Gate。

当前human-v1的Bot受理Worker未装配ReporterDirectoryPort，首次人员读取降级后也没有补全；工单展示又依赖原消息24小时留存。将工单必要来源与人员资料作为受控业务记录随Ticket持续保存，解决未完结及已完结工单丢失联系资料的问题。原始消息、正文、媒体、会话投影和发送权限仍沿各自原留存规则。

## 决定

- 新增`intake.ticket_reporter_profile`，覆盖Bot、H5和人工代录，关联现有Unified Ticket及其不可变原始Intake，保存来源渠道、来源Provider、Reporter HMAC、姓名、部门名称、资料来源与取得时间，以及有界补全状态。它不拥有Ticket编号、状态、责任或事件，不复制人员主档，也不保存手机号、头像、令牌或原始Bot身份。人工代录保持已核实／未核实标识，不因投影自动查询或认定人员身份。
- 该业务记录随Ticket持续保存，完结、取消、重复关联和重新打开均不因时间自动清理。获权读取仍每次核验当前Ticket READ，终检及退出清理不放宽。
- 原始报修时Journey快照保持不变。已有成功快照可投影为`REPORT_SNAPSHOT`；后来通过当前应用成员读取取得的资料保存为`LATER_LOOKUP`，记录实际取得时间，不冒充报修时快照。
- human-v1增加默认false的显式`workbenchReporterProfilesEnabled`。开启时App和Worker都要求067 Schema；Worker获得最小应用读取配置及APP_SECRET，仍不获得Bot密钥、发送权限、OAuth会话或通知路由。首次受理接入真实人员读取Port；关闭后停止新增采集和补全，不删除业务记录。
- Bot原始身份通过官方`userid_to_openuserid`转换后，使用已有受限成员读取器取得姓名和主部门；核对原Bot、身份HMAC、返回身份和当前应用成员资格。H5只使用原应用／企业范围内的`APP_OPEN_USERID`及有效的签名收件人证明；等待后重新核验原绑定未撤销且所有身份字段不变。不根据姓名、手机号或ID外观猜测对应关系。Provider失败不阻断受理。
- Worker在现有周期中投影必要资料并处理持久补全任务。每次最多一个外部补全请求、单并发、2秒交付截止，底层未settle仍占用槽位；最多8次尝试，持久化间隔和领取令牌，重启不重置计数。等待后重新核对Ticket原来源及领取状态，过期领取结果不能覆盖较新的资料。
- 对已有Ticket的修复，仅允许读取原始Intake中必要的来源字段和Reporter身份，用于核验上述业务记录；即使原消息留存已过也不恢复正文、媒体、会话、外发或其他原权限。这是用户明确要求修复的工单资料用途，不是全局延长过期行。
- migration 067仅新增关系、约束、索引和迁移回执，历史SQL不改。回退关闭新开关并恢复前版程序/配置；已取得的业务资料与原快照继续保留。

## 验证与边界

覆盖真实编译三角色入站后自动得到姓名/部门、暂时失败后补全、重启/迟到结果、原快照不覆盖、错误Bot/身份/应用范围拒绝、Provider无发送调用、当前READ撤销，以及原消息过期和工单完结多年后业务资料仍可获权读取。已有历史工单的修复结果单独记录，不将本地合成测试当作现场取得资料。
