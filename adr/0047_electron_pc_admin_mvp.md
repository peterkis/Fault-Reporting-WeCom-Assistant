# ADR-0047：信息科 Electron 桌面 MVP

状态：Accepted，依据用户于 2026-10-26 确认并要求实施的 PC Electron MVP 计划；不代表部署、真实发送或 Gate 批准。

正式 PC 前端继续由既有同源服务提供。Windows 10/11 x64 Electron 仅承载窗口、托盘、扫码入口和通用桌面提醒；Ticket Core、认证、权限、命令、Outbox/Delivery 仍由服务端拥有。此前技术方案中的未来 Tauri 方向由本决定前向取代，历史记录不改写。源码在 `app/pc-admin/desktop`，根依赖与锁文件统一管理，工具及生成文件集中于项目 D 盘 `.local/electron` 并忽略。

主进程使用 strict TypeScript `.mts`，沙箱 preload 使用 `.cts` 编译为 `.cjs`，因为 Electron 沙箱不支持 ESM preload；不通过关闭 sandbox 获得兼容。远程页面没有 Node 权限，窄 IPC 逐次核对主窗口、主 frame、origin 和闭合输入；登录站点没有业务桥。安装包仅含经过白名单选取的宿主文件与非敏感 origin。

2026-10-28 PR审查修补：允许当前已建立员工上下文的业务主frame下载本页面生成的同源附件Blob，仅接受既有固定报修文件名、媒体MIME及大小上限。仍拒绝其他来源、子frame、任意URL/文件名及未知大小；主进程仅设置原生保存对话框，由用户选择目的地，不向远程页面开放路径或文件写入IPC。测试驱动的自动选路仅用于隔离下载验收，不进入安装包。

新增固定 `GET /workbench/desktop`，复用现有员工扫码 state、浏览器绑定和 Cookie，回跳固定 `/workbench/app/`。桌面用途前缀参与完整一次性 state 哈希核验，只有成功消费后才映射固定 SPA 返回路径；数据库继续保存原 `/workbench`，保持035的 return_path 约束，篡改前缀不能消费原 intent。普通 API 401/403、现有登录和退出不变。human-v1 增加可选默认 false 的 `workbenchRemindersEnabled`，只传 App；保留 H5 已有提醒装配，不新增数据库或自动迁移。

桌面背景提醒复用同一 SSE/刷新时钟与现有只读提醒。实际窗口显示、焦点、锁屏和挂起与后台传输分开：隐藏不产生已读、查看或编辑续租；断线/睡眠/身份变化后重新建立提醒基线，不补响历史。点击通知是显式定位意图，仍须 READ 与草稿/UNKNOWN 导航保护。普通浏览器保留原可见性规则。

用户主动开启提醒，声音默认关闭。退出、重新登录、刷新和升级不得绕过未提交/未确认操作保护；关闭到托盘保留当前页面。首版保持 human-v1 草稿恢复关闭，使用普通安装包和手动升级，不加入自动更新、开机启动或本地业务数据库。实际 Windows 通知及多机试用独立验收，合成通过不代替现场批准。

实际三人 Electron 接单竞争复现了回执外键 KEY SHARE → 流 advisory → Ticket FOR UPDATE 的锁升级死锁。沿既有完工/分派模块模式，在两条本人接单服务中把原流锁移到回执插入之前，并在等待后重新核验 Ticket 与选择 Session 的 READ；原业务终检、版本、事务、receipt、失败记录和事件语义保留，不增加盲重试或修改旧 SQL。

2026-10-27 按用户明确要求，桌面业务页收到可信的认证失效 401 后，沿原撤权路径停止旧页面与桌面提醒、清理恢复副本，再自动调用已有 `requestLogin` 进入固定企业微信扫码入口，不再要求点击失效提示页。并发失效共用正在进行的清理；清理未确认时保持关闭并显示恢复提示，不跳转、不重放业务命令。403 权限不足、网络/服务故障及主动退出保留原处理。此后继只改服务器提供的 PC 前端，不扩大 IPC、凭据寿命或权限，也不要求重装客户端。

2026-10-26 按用户后继选择，0.1.2 将标题栏和三个窗口按钮全部自绘，原菜单收进“更多”。可信本地标题栏由无系统框架的 BrowserWindow 承载，既有远程页面放在下方独立 WebContentsView 中；不注入远程/扫码页面的DOM，不改服务器UI或OAuth origin/session。业务IPC仍只允许该业务view的当前主frame和获准origin；窗口操作IPC只允许本地chrome主frame及四个固定动作。显式退出先让业务view执行beforeunload，确认销毁后再关闭父窗口；关闭按钮继续隐藏到托盘。旧浏览器入口、草稿保护、通知及责任事实保持。

2026-10-29 按用户要求，0.1.9在登录态收起整条品牌/版本/应用菜单栏，远程登录内容覆盖窗口内容区，挂绳从上沿伸入。最小化、最大化和收起到托盘三个按钮放在单独的透明本地控制view中，顶部透明空白区域仍可拖动窗口；业务态恢复原40px本地标题栏。窗口IPC只接受原本地主frame或这个精确拥有、URL固定的本地控制view主frame；后者仅允许三种窗口动作，不允许打开应用菜单。远程登录页及企业微信iframe继续没有窗口/业务桥。两个子view均须在父窗口销毁时关闭，退出及未提交保护保持。页面更多登录入口使用既有Lucide React图标和浏览器原生popover，不创建另一套认证或原生窗口权限通道。

2026-10-30用户明确要求登录菜单能够完整退出程序、工牌背面显示实际客户端版本，并关闭窗口减动偏好。0.1.10新增独立登录展示桥，仅暴露读取包版本与请求完整退出两个固定动作；主进程逐次核对拥有的content view、主frame、配置origin及无query/hash的精确embedded路径。它与业务桥/本地标题栏桥分开，企业微信子frame、其他origin和业务页不获得此桥。退出复用原requestQuit及beforeunload/未确认保护，不新增硬杀进程能力；右上角关闭仍保留收起到托盘语义。

内容view在首次真实导航前，以主进程私有的Emulation.setEmulatedMedia设置窗口prefers-reduced-motion=no-preference，不更改Windows设置，也不开远程调试端口或向页面开放协议能力。先加载自有about:blank使目标就绪，再设置固定媒体偏好；应用默认完整动效，--wecom-reduced-motion显式选择reduce作为应急备用。该协议仅服务此受控展示设置，权限、证书、origin、认证和业务终检保持。

2026-10-30用户授权离线及黑屏后恢复：桌面壳在远程文档不可用时展示本地离线/重连界面，持续以有界间隔等待联网，聚焦/解锁/恢复也触发检查。恢复只重新打开安全GET文档，不重放认证callback或业务写入；原未提交/UNKNOWN及beforeunload保护仍有效。业务文档401进入固定登录页并提示重新登录，403/证书/服务错误保留区别。渲染进程退出恢复使用独立频率上限，不因黑屏推断实际发生系统休眠；不新增持久业务缓存或扩展登录寿命。
