# ADR-0045: Versioned current readiness after the application layout migration

Status: Accepted for implementation by the user's explicit repair-plan request, 2026-10-24. Local checks, strict certification, live permission and Gate approval remain separate.

The current application has 49 accepted SQL files, while [ADR-0027](0027_yxx_current_readiness.md) deliberately pins an earlier 22-file combination. Its exact rejection is correct. Updating a count or accepting the directory contents would lose that boundary, so the current CLI moves to an explicit versioned successor; the predecessor inputs and historical evidence stay unchanged.

## Local engineering budget

The measured two-build gate retains its 360-second subprocess budget, both strict emits, every build/resource guard, complete artifact verification, determinism comparison and real selected/canary execution. Every ordinary build starts all compiled-file `node --check` commands with the existing two-child bound. Only the second build in the same gate process may reuse the first build's successful syntax proof when the full source identity, root, actual compiled path/byte set and actual Node executable hash/options are identical. The proof is an in-memory capability created after successful checks and sealing; a JSON manifest cannot supply it. Changed inputs, outputs or Node identity require real checks again. Logs distinguish actual checks from reused coverage. All current source, index, history, catalog and physical-output checks continue to read their actual inputs; this does not cache a readiness decision or replace either compilation.

Negative architecture probes that remove a scope or alter historical Evidence must operate in an owned checkout. A forced timeout must not leave a temporary mutation in the user's source tree. The normal complete ARCH006 CLI remains exercised. Its negative structure case checks the real scope and history rejection APIs independently, then verifies both denial messages in one complete CLI execution against the owned checkout. This removes the measured repeated unrelated architecture scan while retaining each refusal, the CLI wiring, actual history reads and the original case/subprocess budgets. Fixture ownership and the unchanged original bytes are recorded separately from process-tree cleanup.

The current repair is local and uncommitted. Its actual working-tree and artifact fingerprints identify the work; the existing HEAD is not relabeled as its tested commit. This task does not publish a certification packet or rewrite the current evidence pointer. `STRUCTURE_VALID_NOT_READY` is structural success only.
