# 会话运行与交付

长任务、故障诊断、并行工作、发布及清理时读取本页。事故依据见[复盘索引](../retrospectives/README.md)，业务完成标准见[开发边界](development.md)。

## 先确认来源

1. 读当前 Issue/合同、工作区差异及实际执行入口。历史交接里的“当前”只适用于其记录日期和候选。
2. 把本地 SHA、GitHub PR head、审核临时快照、被测祖先、编译 manifest 分开记录。涉及历史断链先按[历史审查规范](../../.github/review/README.md)确认对象。
3. 给结论标明对象、环境和范围：源码/编译/historical、local/CI/live、入口/用例、PASS/FAIL/NOT_RUN。另一 head 的通过不补本次漏跑。
4. 阅读本地 JSONL 时先用 `session_meta` 筛项目和父子关系，再定向读取事件。活动会话只绑定固定读取前缀/截止时间；压缩归档先按实际格式读取，不因只查 `.jsonl` 漏掉 `.jsonl.zst`。

## 凭据与身份

- 调用 Provider 前先确认身份命名空间及其转换合同，区分企业成员 ID、应用开放 ID、内部 principal 和 Reporter 绑定。格式相似、名称相同或一次 API 成功均不能证明可互换。
- 日志只输出字段白名单：阶段、错误类型/安全错误码、响应状态、计数和脱敏摘要。异常对象的 URL、headers、response、cause、stack 也可能含凭据；检查打印路径后再调用，不把带认证 query 的完整 URL 或环境对象交给工具输出。
- `DATABASE_URL`、token、授权码、个人目录原值和原始诊疗数据不进入公开日志、Issue、PR 或复盘正文。保留来源路径/行号及脱敏结论即可。
- `check`、READY、本地 PASS、局部定向现场和完整现场 Gate 各有适用范围。环境修复不自动授权再次真实写入/发送；按原批准的对象、窗口、停止条件执行。

## 单写者与并行

- 按真实未阻塞 frontier 并行；Contract、迁移编号、测试宿主和负责路径先分配。并行源码任务使用隔离 checkout，或明确不重叠的写入路径；不要让两个会话在同分支交叉改写同一候选。
- 一个 checkout 的源码、Git 和自有 runtime 同时只有一个写者。交接包含 head/tree、差异路径、构建/测试原件、资源状态和明确 STOP；Root 收到后再整合。
- 只读审查可并行。子任务不自行推送、评论、关闭 Issue、合并或清理其他任务资源。用户对后续操作的明确授权沿用；不要用旧轮次“仅发票”限制否定已授权的新阶段。

## 定位失败

1. 保留第一次失败和原调用参数，提出能被观测推翻的假设。检查现有日志、TAP、case trace、截图及实际加载文件，优先做一次原路径观测。
2. `fetch failed` 加用例声明行只能定位到 case，不能指出失败 await、连接复用或服务端根因。需要时记录安全阶段、原 Error/一层 cause 和实际收到请求数；收到请求不等于已成功响应。
3. 自然 PASS 只说明该次未复现，不写成修复前 RED。把观测用临时改动与正式构建分开；临时编译注入结束后按原字节恢复，再生成正式候选。
4. 跨 reload/导航的等待同时确认新文档与当前事项的真实响应，避免在旧 DOM 上提前满足。控制/投影时序使用现有 drain 或服务端序列边界，不添加任意 sleep 来绕过断言。
5. 测试不以同 TCP 端点为业务合同，却在一个客户端生命周期内停止/重建 host 时，检查端点与客户端是否耦合。保留同 PG/事实、原主体/flags、真实新认证及全部断言；确需相同 origin 的恢复合同保持原样。
6. 检查 Source、staged Runtime、固定 historical 根以及实际 SQL profile。库存超限先核对根选择；固定22项 profile 对当前45项的前置拒绝，不能作为后续 fingerprint 断言失败的证据，也不靠提高上限“修复”。
7. 修补当前直接风险；已有测试/原门禁可复用时不再建立平行认证器。具体检查见[验证规则](validation.md)。

## 工具与输出

- 先读接口/`--help`/实际 JSON keys，再写包装脚本；字段名、函数签名和返回 shape 不靠猜。批量独立只读查询，保留依赖操作顺序。
- Windows 传给外部 `rg` 的文件 glob 用 `-g '*.mts'` 加目录，不假定 PowerShell 展开 `dir/*.mts`。复杂 Python/PowerShell 放到已知 D 盘任务目录的文件中，先做语法解析，再执行；正文用 `--body-file`。
- 文本表示分别保留 Git LF、工作区 CRLF、实际编译文件的原始大小和哈希。先证明仅 EOL 差异再作归一化比较；不要将真实用户未提交内容误称换行差异。
- 大 JSON 只输出 keys、counts、失败条目和原件路径/哈希；原始文件留在任务目录。一次工具输出容不下的多份全文不一起打印。
- 等待异步测试或下载使用有界等待和合理间隔，避免秒级空轮询。状态不变时不重复拉取整份 PR 评论；仅变化时读具体线程/制品，并向用户说明有意义的阶段变化。
- 下载制品使用现有 CLI/API；受控分段下载时，认证头只发给 API 原站，签名下载请求不携带它。逐段长度、完整 zip CRC、来源 SHA、manifest 和逐例文件均核对后才消费结果。

## 审查与合并

- 工具不可用、未选中目标文件、无可用规则或未实际调用模型，都不能标审查 PASS。使用用户授权的原 Code Review 回退时，明确 Standards/Spec 及所审 head/范围。
- 对每条真实问题记录诊断、修补、适用测试与是否已解决。修复后检查线程状态，避免只推代码却漏掉已授权的 thread 收口。对外回复仍沿本次授权范围。
- 合并前核当前完整 head 的已完成审查、未解决线程与全部适用 CI；下载原件确认执行数和 NOT_RUN。只读文档更新不自动要求重建业务候选；按[历史审查收口规则](../../.github/review/README.md)处理范围。
- 已获用户授权的合并保留真实被测祖先，使用 merge commit 和 `--match-head-commit`。普通 PR 的 CI 不替代 full/certify 或现场批准。
- 合并后先证明本地 `main` 从旧点真实快进到远端新点、tree/父链正确且 ahead/behind 为0，再开始清理。

## 清理与证据

- 先对已提交改动、自有 checkout/branch/PG/browser/profile/cache 建白名单，核完整绝对路径、D 盘包含关系、无符号链接/重解析点、无活动进程及真实祖先关系。非自有、未合入、移动过或无法确认的对象保留。
- 库只精确删除本任务新建的 UUID 合成库并核原库清单恢复；PG 停止后记录 status、PID/监听、配置摘要及 keeper 状态。错误与清理错误独立保留，不覆盖主错误。
- 缓存中的文件若被历史 manifest 引用，删除前先独立保存原字节和来源→备份映射，保持旧 manifest 不变。共享源码、原始 Evidence、失败中间态、stash 与恢复引用保留。
- Git 工作树、实际目录与应用挂载是三种状态，分别读回。应用元数据通过支持的 API 清理；“owned by another task”属于归属拒绝，不能冒充成功，也不改应用数据库或强删其他任务文件来绕过。
- 最终记录实际删除、已归档、保留与拒绝项。归档只针对本任务已 STOP 的子任务；保留主会话和不相关任务。
