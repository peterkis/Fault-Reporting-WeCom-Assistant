## 2. 高风险项

### R01 群聊触发方式与预期不一致

应对：

- Gate 0；
- V1 明确要求 @机器人；
- 不采用 Windows RPA；
- 必要时调整临床操作说明。

### R02 图片能力不稳定

应对：

- 文本先建单；
- 图片异步；
- 私聊或 H5 上传作为降级；
- 不让图片失败阻断报修。

### R03 企业微信主动通知表现不满足群内 @

应对：

- 个人进度单聊；
- 群内公共卡片；
- 实测后决定是否保留 Webhook 备用；
- 不在 PRD 中假定未验证的 @ 行为。

### R04 Tickets 接口不完整

应对：

- 先补齐内部 API；
- 不直接写 Tickets 数据库；
- 使用 Adapter；
- 将状态机建设列为 Phase 2。

### R05 身份和组织映射不完整

应对：

- 允许 userid 先创建 Intake；
- 管理员映射队列；
- 保留原始组织快照；
- 院区和故障发生科室可后补。

### R06 群消息噪声

应对：

- 默认仅处理明确发给机器人；
- 群内减少状态广播；
- 个人进度单聊；
- 通知合并和限流。

### R07 错误公共故障关联

应对：

- 默认人工确认；
- 高精确率门槛；
- 支持 unlink；
- 保留独立 Intake；
- 不简单按时间类别并单。

### R08 CPU 推理排队

应对：

- AI 异步；
- 规则优先；
- 模型按需调用；
- 并发限制；
- 可关闭 AI；
- 不影响首次回复。

### R09 患者数据进入截图

应对：

- 私有对象存储；
- 脱敏；
- 访问审计；
- 留存策略；
- 不出院；
- 不写日志。

### R10 项目范围过大

应对：

- Gate 0 → 无 AI 闭环 → OCR → AI → Incident；
- 每个阶段独立验收；
- 禁止跨阶段开发；
- MVP 先 H5，不急于原生小程序。

## 4. 决策管理

开放问题形成结论后：

- 更新相关文档；
- 更新 `plans/master_backlog.json`；
- 核心变化新增 ADR；
- 记录日期、决策人、替代方案和影响；
- 不允许仅在聊天或代码注释中冻结架构决策。
