## R29-01：先验证装配，再解释为数据过期

S02 最初把姓名/部门缺失解释为历史材料超过保留期。继续核查实际编译 Worker 后，才发现 `directoryPort` 未接入、首次 `DEFERRED` 后缺少 Bot 补全，以及 Ticket 必要资料被原消息 TTL 遮蔽。用户又明确要求完结后仍随工单保存，最终通过 ADR-0048、067 和实际进程路径修复。原消息、身份引用、后补资料及采集时间分别保留，资料缺失没有靠猜填解决。

今后同类问题先沿 HTTP 投影、持久资料、Worker 配置及 Port 的实际调用链定位；同时区分从未采集、暂不可用、读取期满和展示缓存。规则落在[失败定位](../agents/session-operations.md#定位失败)，具体合同与已修复过程见[资料生命周期记录](../../plans/pc-admin-electron/reporter-lifecycle-2026-10-27.md)及[资料测试](../../tests/ticket-reporter-profiles.test.mts)。这次不修改留存合同或再做现场补录。

## R29-02：性能修复要证明开销不再随结果数量增长

S02 先将 50 卡片从 664 次 SQL 降到 321 次、约 1.9 秒；用户指出仍不合理。真实 PG/HTTP 对照随后证明旧路径是 `21 + 6 × 卡片数`，批量化后 1/10/50 卡片固定 22 次 SQL，另一正式装配组合固定 23 次。端到端 HTTP、单条 SQL 的 `EXPLAIN ANALYZE`、预热和首次请求分别报告；夹具准备后的首次请求没有冒充磁盘冷读。

S01 媒体同样存在按 64KiB 块重复查询的放大。按显式批准的 ADR-0050，PC 员工路径改为请求级核验；合成七预览从 812 次 SQL、约 6.45MB 降到 21 次、约 70KB。该权限变化只适用于具名 PC 路径，H5 的原终检合同保持。两组数据分别属于各自候选与环境，不拼成同一次云端性能证明。

现有[看板修复记录](../../plans/pc-admin-electron/board-performance-2026-10-26.md)、[媒体交付](../../plans/pc-admin-electron/media-employee-read-2026-10-28.md)和[员工媒体集成测试](../../tests/workbench-media-employee-read.integration.test.mts)已有数量断言。本次在[风险验证导航](../agents/validation.md#按风险选择已有验证入口)补上选择依据，不新增同义性能框架。

## R29-04：环境预检先于切换，恢复使用新尝试身份

2026-10-29 首次激活前，新候选通过 47 项组件及合成视频封面检查，070 已应用；公网验收才发现证书在当天 07:59:59（Asia/Shanghai）过期，自动恢复旧实例。原版同样不能通过公共 TLS，后端 ready 通过并不能证明入口可用。流程没有忽略证书错误，但如果提前从客户端和代理侧使用正常 CA 检查，可在停服前发现这一外部阻碍。

另一个前置问题是 067–069：旧部署使用 LF 字节，Windows 检出为 CRLF，数据库按原始字节记 checksum。规范化文本相同不等于迁移身份相同。发布使用经核验的旧部署原字节冻结兼容包，并如实记录 `source_dirty=true`；保留 Git 内容、旧 marker 和首轮失败，冻结后恢复主目录原字节并重建。不能把此包与通常的干净 main 制品写成同一原始身份。

证书由另行授权的维护恢复后，使用新的预检、owner 和 `attempt-02`，重新绑定现有 30 条迁移、证书及 Nginx 哈希；070 check/apply/check 均为 NOOP。APP/WORKER 实际进程的三个目标开关为 true，GATEWAY 均为 false，32 项健康检查、正常 TLS 和匿名媒体 401 通过。旧失败和回退仍保留，真实业务视频样本与登录后体验没有因此变成 PASS。

本次将该顺序写入[发布前只读预检与失败后续作](../runbooks/human-workbench-runtime.md#发布前只读预检与失败后续作)，并把实际启用状态追加到[交付记录](../../plans/pc-admin-electron/media-employee-read-2026-10-28.md#2026-10-29-独立授权启用与清理观察)。没有在本次复盘连接云机、更新证书或重新发布。

## R29-07：检查生成后的实际文件，交接保留执行层级

S01 上传辅助脚本时出现嵌入代码转义错误，后续归档生成器也在本地语法检查失败；相关辅助失败、断点恢复和哈希核验保留。检查应针对最终生成/上传的每份文件，前一步退出成功才执行后一步，避免生成器失败后仍调用不存在的下游文件。实际子进程配置来自 env-file 和角色环境，仅查看容器 `Config.Env` 会漏判有效开关。

A01–A03 交接明确标了静态通过、编译/PG/浏览器 NOT_RUN。后续真实 PG 才定位到同一参数按 text/uuid 使用的错误。这证明静态提案有价值，但 Root 整合后的实际运行不能省略，也不能把子任务交付时的 NOT_RUN 回写为 PASS。

工具经济同样存在执行偏差：仓库已有“先 keys/counts、再按锚点读取”的规则，近期仍发生大输出截断。此次用元数据和选定消息/回执定位，最终只保存摘要、锚点与哈希；不再追加同义规则或一套会话平台。对生成脚本的退出门槛只收紧[原工具条款](../agents/session-operations.md#工具与输出)。
