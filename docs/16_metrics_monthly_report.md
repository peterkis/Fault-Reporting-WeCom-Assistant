# 16. 指标口径与月报设计

所有指标必须带 `phase` 与 `ticket_source` 维度。Phase 1/2 的 `ticket_source=PILOT`；Phase 3 切换后为 `HOSPITAL`。迁移期间不得把同一映射对象重复计为两张业务工单。

## 1. 原则

指标必须有清晰分母、时间起点和排除规则。不能用“AI + 人工补录转化率”掩盖系统漏单。

## 2. 受理指标

### 2.1 明确报修捕获率

```text
形成 Intake 的明确机器人报修数
/
企业微信实际投递的明确机器人报修数
```

目标：100%。

### 2.2 工单创建成功率

```text
成功生成 Ticket 的需建单 Intake
/
需建单 Intake
```

区分即时成功和重试补建成功。

### 2.3 重复建单率

```text
重复 Ticket 数
/
唯一报修消息数
```

目标：0。

## 3. 时效指标

### 3.1 首次确认时间

```text
wecom_received_at
→ first_reply_accepted_at
```

### 3.2 首次受理时间

```text
ticket_created_at
→ accepted_at
```

### 3.3 开始处理时间

```text
ticket_created_at
→ in_progress_at
```

### 3.4 解决时间

```text
ticket_created_at
→ resolved_at
```

### 3.5 关闭时间

```text
ticket_created_at
→ closed_at
```

等待申报人和等待厂商时间应分开统计。

## 4. 质量指标

- 用户确认解决率；
- 超时自动关闭率；
- 重开率；
- 一次解决率；
- 超 SLA 工单率；
- 待补充超时率；
- 通知送达率；
- 人工分诊率；
- 身份映射失败率。

自动关闭不能计入用户确认解决。

## 5. AI 指标

### 5.1 分类

```text
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
```

分别统计：

- request_type；
- system_code；
- symptom_code；
- resolver_team。

### 5.2 覆盖率

```text
AI 给出可用建议的 Intake
/
进入 AI 的 Intake
```

覆盖率不能替代准确率。

### 5.3 人工修正率

按字段统计：

- system；
- symptom；
- location；
- team；
- incident candidate。

### 5.4 Schema 成功率

严格 JSON Schema 通过率。

## 6. 公共故障指标

- Incident 数；
- 每个 Incident 关联申报数；
- 受影响科室数；
- 识别提前量；
- 人工确认时间；
- 错误关联率；
- 解除关联数；
- 重复处理任务减少量。

## 6.1 Phase 3 迁移指标

- Pilot/Hospital 映射覆盖率；
- 幂等重复抑制数；
- 未解释对账差异数；
- 迁移失败与重试数；
- 切换后仍写入 Pilot 的正式工单数（目标 0）；
- 双重通知数（目标 0）。

## 7. 临床体验指标

建议通过简短评价或抽样：

- 是否及时收到确认；
- 是否清楚当前状态；
- 是否减少重复催问；
- 是否认为信息科响应更透明；
- 卡片和 H5 是否易用。

不建议在每张工单强制长问卷。

## 8. 月报结构

### 第一部分：总体

- 报修量；
- 工单量；
- 公共故障量；
- 活跃科室；
- 核心 SLO。

### 第二部分：服务效率

- 首次确认 P50/P95/P99；
- 受理时间；
- 解决时间；
- 超 SLA；
- 积压趋势。

### 第三部分：故障分布

- 系统；
- 故障类型；
- 院区；
- 科室；
- 时间段；
- 重复问题。

### 第四部分：服务质量

- 用户确认；
- 重开；
- 自动关闭；
- 通知失败；
- 投诉和意见。

### 第五部分：AI辅助

- 影子分类准确率；
- 自动建议覆盖率；
- 人工修正；
- 模型延迟；
- 降级时段。

### 第六部分：改进建议

- 高频系统；
- 高频科室；
- 可形成知识条目的问题；
- 需要治理的账号、终端、网络或接口问题；
- 下月重点。

## 9. 数据解释

月报必须注明：

- 统计周期；
- 工作时间定义；
- 排除的测试数据；
- 自动关闭口径；
- 公共 Incident 与 Ticket 的关系；
- 统计所用 Phase、ticket_source 与切换时间；
- 指标缺失或数据质量问题。
