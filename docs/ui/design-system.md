# 医小修 PC 管理端 · 统一设计系统规范 v2.0

Oct 31, 2026 · @peter evans

## 结论

页面难看的根因不是「Airbnb + Notion」这个方向错了，而是**没有一个被代码强制执行的设计系统**：v1.0 规范只覆盖了看板、列表、抽屉三屏，之后每个功能（会话、通知异常、新报修、附件、语音、处理记录、设置……）都在各自的 CSS 里自己定颜色、字号、圆角；10-28 引入 HeroUI 后又叠加了第二套 Token。结果是三套视觉语言同时在屏幕上说话。

本规范（v2.0）给出的决策：

1. **一个底层语法**：以 Notion 的「工具型密度 + 中性灰阶 + 发丝线」为骨架；Airbnb 只贡献「温度、单一品牌色、浮层质感、友好文案」四样东西，且只出现在规定位置。
2. **一套 Token、三层结构**：原始值 → 语义 Token → 组件 Token；HeroUI 的 `--accent / --border / --surface` 全部由语义 Token 派生，功能 CSS 禁止写裸值。
3. **一套页面模板**：所有一级页面共用同一个 PageHeader + Toolbar + Content 骨架，宽度、标题、间距不再按页面各写一份。
4. **一张状态语义表**：状态只在一个地方定义颜色，来源/渠道一律中性灰，人名永远不做成彩色标签。v2.1 类别瓷砖按第四章采用服务目录大类色。
5. **用 lint 守住**：Stylelint 禁裸 hex / 裸 px 字号 / 未定义变量，CI 卡死，否则三个月后会再次漂移。

### 1.2 视觉层：截图里直接看得见的问题

**团队工作台（看板）**

- **标题区过重**：64px 图标瓷砖 + 36px/700 标题 + 句式副标题，占了首屏约 15% 高度，是营销页写法，不是工作台写法。「人工协作」徽标孤零零挂在右侧。
- **内容居中留白不对**：1240px 容器在 1920 屏上居中，左侧留出大片空白，而会话页又是左对齐铺满——两页切换时标题位置跳动。
- **状态表达了三次**：列头有黄色「待受理」胶囊 + 整列米黄底色 + 卡片内又有黄色「待接单」标签。三列底色（米黄/淡蓝/淡绿）使整板发花。
- **标签语义不清**：一张卡可同时出现 待接单(黄)、H5报修(灰)、本轮已催单(橙)、补充待跟进(橙、还换行)。「已领取」与「待接单」同色、却表示不同阶段。
- **卡片内部节奏乱**：编号(等宽 12) → 标题(15/600) → 报修人·科室(13) → 标签行 → 底部处理人+时间；处理人「冯刚」与报修人「冯刚」重复出现且样式不同，没有超时信息。
- **工具栏两行断裂**：第一行页签 + 按钮组，第二行「已加载 8 项」+ 日期筛选；「应用 / 清除」两个按钮形态不同。

**工单详情抽屉**

- **主操作色源不对**：「登记完工」是硬编码 `#315fed` 亮蓝，全站其他地方没有这个蓝。
- **「派单」按钮悬空**：右下单独一行，与顶部操作区割裂。
- **区块标题无层级**：报修描述 / 报修资料 / 报修人通知 / 处理记录 全是 14/600，而「处理与协作」又是灰色折叠文字，读不出它们是同级。
- **人名做成彩色标签**：处理记录里「冯刚」是青色胶囊、「系统」是黄色胶囊，与状态标签长得一样，读者会把人当成状态。「内部」又是带描边的第三种标签样式。
- **通知时间线孤立**：一个蓝点 + 文字堆叠，没有与下方处理记录共用时间线组件。

**会话页**

- 标题无图标瓷砖、左对齐，与工作台模板不同；副标题与分割线紧贴，没有留白。
- 搜索标签在上、输入框在下、「搜索」按钮另起，三个元素高度不同；两个下拉框带外置标签，而工作台的日期筛选是行内标签——同一类控件两种写法。
- 空状态提示「当前筛选没有获权联系人」被挤到列表底部，与右侧大空状态各说各话；分页按钮在没有数据时仍占位。
- 右侧 1300px 宽的空白只放了一个小图标 + 两行字，句子在「责」处断行。

### 1.3 根因归纳

1. **规范覆盖面太窄**：v1.0 只定义了 3 个屏幕，没有定义表单、筛选、空状态、弹窗、时间线、媒体、分栏布局等「通用积木」，新功能只能自己发明。
2. **两套 Token 并行**：HeroUI 接入时只覆盖了部分变量，按钮、字段圆角（5px）与自建的 6px 不同，主色变成近黑。
3. **没有组件层**：标签、区块标题、字段行、空状态都是每个 feature 用 class 自己拼，而不是 `<Tag tone>` / `<Section>` / `<EmptyState>` 这样的共享组件。
4. **风格融合发生在组件级而非层级**：Airbnb 的大标题、大瓷砖、色块列与 Notion 的小字号、发丝线、灰按钮逐个组件混搭，形成「大头小身」。下一章解决这一点。
5. **没有自动化约束**：库里有 CI 门禁，但没有任何样式层面的检查，Agent 生成代码时自然就会写裸值。

## 二、方向：Airbnb × Notion 按「层」融合，而不是按「组件」混搭

两者的设计目标不同：Airbnb 是消费级、低频、以图片和转化为中心；Notion 是生产力、高频、以文字和密度为中心。信息科工程师一天盯着工作台几小时，**骨架必须是 Notion**；Airbnb 只用来提供「人情味」和「精致度」，并且被限定在以下层。

| 层 | 来源 | 具体做法 | 不要的做法 |
| --- | --- | --- | --- |
| 信息密度与布局 | Notion | 14px 正文、32px 控件高、浅灰侧栏、属性表、发丝线分隔、整宽工作区 | Airbnb 的大留白、居中窄容器、36px 大标题 |
| 中性色 | Notion 暖灰 | 全站只用一组暖灰（`#37352F` 系），不再混入 Tailwind 冷灰 `#64748b/#e5e7eb` | 两套灰混用 |
| 品牌色 | Airbnb 方法论 | **一个**自信的品牌色（医小修蓝 `#2563C9`），只用于：每屏唯一的主按钮、当前选中、链接、未读点 | 照搬 Airbnb 玫红：在医院语境里红色留给「危险/超时」 |
| 浮层质感 | Airbnb | 抽屉、弹窗、下拉弹层用 12–16px 大圆角 + 柔和大阴影；卡片悬停轻微抬升 | 静态卡片大圆角、大阴影 |
| 媒体 | Airbnb | 附件图片网格 8px 圆角、统一比例裁切、悬停微放大 | 不同尺寸描边盒 |
| 空状态与文案 | Airbnb | 友好、具体、告诉下一步；空状态居中、有插图标、有动作 | 制度化、权限术语直接暴露（「获权联系人」） |
| 标题节奏 | 折中 | 页面标题 24/600，去掉 64px 瓷砖，改 20px 行内图标；副标题可选 | 每页一句 slogan |
| 协作信息 | Notion | 小头像 + 姓名纯文字、时间线细线、「内部」纯文字小标记 | 姓名做成彩色胶囊 |

一句话的风格定义：**「像 Notion 一样安静、密、可扫读；像 Airbnb 一样在弹层、图片和空状态里有温度；全屏只有一种蓝、一个主按钮。」**

## 三、设计原则（按优先级）

用词：**MUST** 必须；**SHOULD** 默认应当，偏离需写理由；**MUST NOT** 禁止。

1. **一屏一个主操作**（MUST）：品牌蓝实心按钮每个可见区域（页面、抽屉、弹窗）最多 1 个。工作台是「新报修」，抽屉是当前状态下的下一步（领取 / 开始处理 / 登记完工）。
2. **颜色承载明确的信息**（MUST）：v2.1 分为阶段 / 紧急 / 类别 / 人四层，颜色面积与信息重要程度成正比；来源、渠道、科室、人名文字保持中性。类别只用统一瓷砖，人物色只用于已有稳定哈希头像；品牌操作色沿既有规范。
3. **同一信息只表达一次**（MUST）：看板列已表明阶段，卡片内不再重复阶段标签，只显示「阶段内子状态」（如已领取）。
4. **层级靠字重与灰度，不靠字号堆叠**（MUST）：字重只有 400/500/600 三档；字号只有 6 档（见 Token）。
5. **容器隐形**（SHOULD）：分区优先用间距，其次发丝线，最后才是背景色块；禁止嵌套盒子（框内再加框）。
6. **同类事物同一样子**（MUST）：所有页面用同一个 PageHeader；所有筛选用同一个 FilterBar；所有时间线用同一个 Timeline。
7. **不只靠颜色**（MUST）：超时/异常必须同时有文字或图标；文字对比度 ≥ 4.5:1。
8. **温度只在边界上**（SHOULD）：弹层、图片、空状态、成功反馈可以柔和友好；主工作区保持安静。

## 四、Design Tokens

Token 分三层：**原始色板**（`--gray-*`、`--blue-*`，只在 tokens.css 内部引用）→ **语义 Token**（`--text-* / --bg-* / --border-* / --tone-*`，业务 CSS 只用这一层）→ **HeroUI 桥接**（`--accent / --border / --surface` 全部从语义 Token 派生）。完整可用的 `tokens.css` 随本规范一起交付，内含旧变量兼容映射。

| 60–240 分钟（不含 240） | attention / N 小时 | attention |
| ≥ 240 分钟 | danger / 超时 N 小时 | danger |

分钟与小时均向下取整；缺失、无效或未来起点、非有限 nowMs 返回 null。ring 是语义键 `null / 'attention' / 'danger'`，由共享组件引用对应 `--ring-*`。输入必须为带时区的 ISO 时间，避免浏览器本地时区改变热度。待受理计时取 created_at，处理中取进入当前状态时间（挂起取挂起时间），已处理不计；消费方选择起点，不得用 updated_at 代替。当前 API 的状态起点由卡 11 补齐，卡 9 不修改 API 或页面状态。

### 4.4 层级与动效

- z-index：sticky 10 → dropdown 40 → drawer 50 → modal 60 → toast 70 → tooltip 80，禁止其它数字。

- 抽屉从右侧 16px 位移 + 淡入；弹窗 0.98→1 缩放 + 淡入；卡片悬停只变阴影不位移。尊重 `prefers-reduced-motion`。

### 4.5 焦点规则（修订 10-29 版本）

10-29 的「全站去掉焦点环」解决了鼠标点击出现黑框的问题，但也让键盘用户看不到当前位置。v2.0 规则：鼠标交互不显示焦点环（保持现状）；仅 `:focus-visible` 显示 `0 0 0 2px var(--border-focus)`，输入框聚焦用 1px `--border-focus` 描边 + 白底。

## 六、组件规范

每个组件是 `src/design/components/` 下的一个共享 React 组件，feature 代码只能组合它们，不能再用 class 自己拼一个「长得像」的。

### 6.1 按钮 Button

| 变体 | 外观 | 使用场景 | 每区域数量 |
| --- | --- | --- | --- |
| `primary` | `--brand` 底、白字 14/500 | 当前区域唯一主操作：新报修、登记完工、提交 | ≤ 1 |
| `secondary` | `--bg-canvas` 底 + 1px `--border-default`、主文字 | 重要但非主要：派单、转交、应用筛选 | ≤ 3 |
| `ghost` | 无底无框、secondary 文字，悬停 `--bg-hover` | 工具栏、刷新、清除、取消、图标按钮 | 不限 |
| `danger` | `--tone-danger-fg` 文字、红色描边 | 撤销、关闭工单等不可逆操作，必须二次确认 | ≤ 1 |

- 尺寸：sm 28 / md 32（默认）/ lg 36；水平内边距 12；图标 16、与文字间距 6；圆角 6。
- 图标按钮：32×32，ghost，必须有 `aria-label` 和 tooltip。
- 状态：hover 底色加深一级；pressed `--bg-active`；disabled 文字 `--text-tertiary`、不降透明度；loading 保持宽度，文字替换为 14px spinner。
- 按钮组顺序：从左到右 ghost → secondary → primary；弹窗底部「取消」在左、「确认」在右。
- MUST NOT：近黑实心按钮（现有 `take-and-start`、`complete-ticket`、`send-conversation-reply` 的 `--text-1` 底色）、任何硬编码蓝。
- HeroUI 映射：`primary`→`variant="primary"`，`secondary`→`variant="outline"`（或自定义），`ghost`→`variant="ghost"`。封装为 `<WbButton tone>`，业务代码不直接写 HeroUI variant。

### 6.2 表单控件

- 输入 / 下拉 / 日期全部：高 32、圆角 6、白底、`--border-default` 1px、内边距 0 10、文字 14（工具栏内 13）。

- 区块标题 Section：14/600 主文字，上 24 下 8，右侧可放 12px 辅助信息或 ghost 按钮；区块之间只用间距，不加分割线。可折叠区块在标题左侧加 14px chevron，标题样式不变。
- 属性表：属性名 13 secondary + 16px 图标，值 14 主文字；缺失值写「未提供」用 tertiary。

### 6.9 时间线 Timeline（处理记录、通知、会话系统消息共用）

- 按日分组，日期 12/500 secondary；每条：20px 头像 → **姓名 13/500 纯文字** → 动作描述 13 → 右侧时间 12 tabular。
- 状态变更写成「待接单 → 已领取」，前后状态用 StatusBadge 小圆点。
- 「内部」「对外」为 12px secondary 纯文字后缀，不加框。
- 通知记录不再是独立蓝点块，而是时间线上一种事件类型（铃铛图标头像），发送状态用 success/danger Tag。
- MUST NOT：姓名做成彩色胶囊。人的区分靠头像颜色（四种柔和色按 ID 哈希）。

### 6.10 会话列表项与消息

- 列表项：高 ≥ 64，内边距 12，圆角 8；32px 头像 + 姓名 14/600 + 右侧时间 12；第二行预览 13 secondary 单行省略；未读用 `--brand` 圆点 + 数字。选中 `--bg-selected`。不加分割线。
- 消息气泡：对方 `--bg-muted`，我方 `--brand-subtle`，内部备注 `--tone-warning-bg` + 锁图标与「内部」标签；正文来自数据的「内部：」原文保留。圆角 8、内边距 8 12、最大宽 72%。

### 6.11 空状态 / 加载 / 错误

- **EmptyState**：居中；40px 线性图标（tertiary）→ 标题 14/600 → 说明 13 secondary（最大 32 字宽）→ 可选 secondary 按钮。同一区域只有一个空状态。
- **Skeleton**：`--bg-muted` 块，圆角与真实元素一致，1.2s 微光；不用转圈替代整页。
- **InlineAlert**：圆角 8、内边距 10 12、tone 底色 + 16px 图标 + 13 文字 + 可选链接动作。
- **Toast**：右下角，`--shadow-3`，圆角 8，最多同时 3 条，4s 自动消失（错误不自动消失）。

### 6.12 弹窗 Modal

宽 sm 440 / md 560 / lg 720；圆角 16、`--shadow-4`；头部 20/600 标题 + 13 说明，内边距 24；内容区滚动；底部操作栏 `--bg-subtle` 底 + 发丝线，右对齐。

### 6.13 头像 Avatar

圆形；尺寸 20/24/32；取姓名最后一字，字号为尺寸 50%、500；四种柔和色按人员 ID 稳定哈希；系统事件用 `--bg-muted` 底 + 图标；未派单用 1.5px 虚线圆。

`--fs-avatar-sm: calc(var(--avatar-sm) / 2)`（20px 头像内为 10px）是头像字形专用 Token，不扩展正文六档字号。

### 6.14 v2.1 卡 8 收尾

- 顶栏在所有一级页面常显面包屑，包括工作台与新报修；右侧仅连接状态与设置入口。连接状态使用现有 `RealtimeView.status`，中性文字，不把连接情况当作业务就绪或送达事实。
- 姓名下显示「部门 · 人工协作 / 只读」，沿用现有展示判定；无部门资料时仅显示角色。窄屏保留原账号菜单的退出与设置能力，以设置图标进入；不扩大任何权限。
- 列尾只保留 ghost「显示剩余 N 项 / 收起」；`N` 是已加载但折叠的条数。「已加载 N 项」放列尾原生 tooltip；服务端「加载下一页」仍单独保留，不冒充剩余总数。
- 通知异常刷新放 PageHeader 右侧 ghost 图标按钮；无数据时不显示分页说明与下一页。副标题为「发送失败或结果待核对的通知。查看不会触发重发。」。
- 工单备注的原刷新按钮移入既有「⋯」，名称为「刷新可用操作」，原读取、阻塞与失权清理不变。工单空态统一「这里暂时没有工单」；具体已处理时间范围保持原提示。

本节依据 [v2.1 方案](design-system-v2.1.md) §4.1、§4.2、§4.4、§4.5；其余色彩、热度、类别及下一步卡随各自任务卡实施。

## 九、工程约束、落地路线与验收

### 9.1 目录与导入顺序

```text
app/pc-admin/src/design/
  tokens.css            第 1–3 层 Token + 旧变量兼容层（本规范附件）
  base.css              reset、排版、焦点规则（替代 heroui-workbench.css 的焦点部分）
  status-map.ts         第七章状态 → tone 映射
  components/           Button Tag StatusBadge SourceLabel Avatar PageHeader Toolbar
                        FilterSelect SearchField Section PropertyList Timeline
                        EmptyState InlineAlert Drawer Modal TicketCard BoardColumn
features/*/             只组合 design/components，原则上不再有自己的 .css
```

导入顺序：`tailwindcss` → `@heroui/styles` → `design/tokens.css` → `design/base.css` → `design/components/*.css` → 极少量 `features/*.css`。

实际入口由 `main.tsx` 先导入 `design/foundation.css`，该文件按上述顺序用 CSS `@import` 接入 Tailwind、HeroUI 与 Token，再加载其余样式。不要在 TypeScript 中直接副作用导入 `@heroui/styles`：包根会解析为 JavaScript 工具导出；显式 `/css` 出口也缺少本项目严格副作用导入所需的类型声明。CSS 入口复用现有构建机制，无需增加声明豁免。

文件位置：`tokens.css` → `app/pc-admin/src/design/tokens.css`；`.stylelintrc.json` → `app/pc-admin/.stylelintrc.json`（与该应用的 package.json 同级，在 `app/pc-admin` 下运行 `npx stylelint "src/**/*.css"`）；本规范导出 Markdown → `docs/ui/design-system.md`。当前代码在该配置下的基线违规为 600 条。

### 9.2 自动化约束（接入现有 gate）

- **Stylelint**：`features/**/*.css` 与 `src/style.css` 禁止裸 hex/rgb、禁止 `font-size`/`border-radius`/`box-shadow`/`z-index` 使用非 `var(--*)` 值、禁止 `!important`、禁止 rem。仅 `design/tokens.css` 豁免。
- **未定义变量检查**：脚本扫描所有 `var(--x)`，不在 tokens.css 或 HeroUI 变量清单内即失败（当前会报 7 个）。
- **JSX 检查**：ESLint `no-restricted-syntax` 禁止在 features 中直接写 HeroUI `<Button variant=…>`、`style={{color…}}`、`className` 含 `status-chip`。
- **主按钮计数**：现有 Playwright 截图用例中加一条断言：每个 page / dialog / drawer 内 `[data-tone=primary]` ≤ 1。
- **AGENTS.md**：增加一条「UI 修改先读 `docs/ui/design-system.md`，只用 design/components；新增视觉模式先改规范再写代码」。

### 9.3 落地顺序（不改业务合同，每步独立可发布）

1. **Token 底座**：接入 tokens.css；全量替换 `var(--fw-medium)`→`var(--fw-semibold)`；删除 `heroui-workbench.css` 中的色值定义。此步视觉变化很小，主要消除两套 Token。
2. **全局替换裸值**：按映射表把 136 个 hex、19 种字号、22 种圆角收敛到 Token；开启 Stylelint（先 warning，清零后改 error）。
3. **骨架组件**：PageHeader / Toolbar / EmptyState / Button 封装，所有一级页面切换。这一步解决「页面之间不一致」。
4. **信息组件**：Tag / StatusBadge / SourceLabel / status-map；重做 TicketCard 与 BoardColumn。这一步解决「看板花」。
5. **抽屉**：Section / PropertyList / Timeline；操作区收拢；通知并入时间线。
6. **会话与其它页面**：Split 模板、会话列表项、消息气泡；通知异常、来源群、新报修切换到 Table / Form 模板。
7. **清理**：删除兼容变量层与废弃 class；`style.css` 目标 < 150 行。

2026-11-01 卡 1 执行确认：直接采用 v2 字号和尺寸，接受本卡因 Token 接入产生的排版及布局变化，替代原任务卡“无布局变化”的验收限制。旧变量兼容层补齐到本章已有语义值；旧 10/14/18/28px 间距分别向上归到 12/16/20/32px，不保留旧字号、控件或头像尺寸。列底统一 `--bg-subtle`，四组旧头像色复用既有 info / attention / review / warning 的底色与前景色。现有表格 900px 横向滚动下界和标题图标容器暂保留，随后续 Table / PageHeader 模板卡迁移；本卡不提前重写页面结构或业务交互。
