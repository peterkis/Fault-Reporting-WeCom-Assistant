## 断言（`tests/pc-admin-card34a-toast-modal.browser.test.mts`）

四种宽度（1920 / 1440 / 1280 / 900）× 四类弹窗（关闭事项、设置、恢复确认、媒体预览）：

1. 弹窗内所有可交互元素（`button, input, textarea, select, [role=radio], [role=checkbox], [role=combobox], a[href]`）逐个滚入视野，中心点 `elementFromPoint` 命中元素本身（隐藏的原生单选 / 复选按其 label 计；禁用按钮命中其祖先也算），且不得命中任何提示、胶囊或列表。
2. 右侧剩余空间 ≥ 提示宽 + 32：视口为 `window` 模式，所有可见提示与弹窗矩形不相交、没有胶囊。
3. 否则为 `chip` 模式：列表隐藏，胶囊高 32、不与弹窗相交、文字为「N 条提示」。键盘：Enter 展开、Esc 收起；Esc 只收起列表、弹窗保持打开、焦点回到胶囊。展开时：弹窗右侧 ≥ 272 时列表在弹窗右侧且不相交、弹窗控件仍全部命中；不足 272 时为浮层（`data-toast-popover=true`）；列表都在胶囊上方。
4. 弹窗关闭后视口回到 `docked`（32D-T 详情内停靠），胶囊消失。
5. Codex 复审：展开列表后焦点回到弹窗内，按 Esc 仍只收起列表、弹窗保持打开、焦点回到胶囊（四类弹窗都测）。
6. Codex 复审：媒体预览撑满最大尺寸（宽 720、高到 `100dvh − 32`）时，900×600 下收起的胶囊变为 32×32 紧凑胶囊放进弹窗旁留白，760×600 下留白都不够，弹窗让出高度（`--workbench-toast-reserve`）后胶囊放在弹窗下方；两者都不与弹窗相交、都在窗口内；回到 1440 后不再让出高度。

结果见 `receipt-34a-toast-modal.json`、`receipt-34a-toast-media.json`（16 个组合加 2 个满尺寸媒体组合全部通过）。

提示数量：关闭事项与设置用 3 条持久提示（内部备注冲突 + 其草稿提醒 + 关注冲突）；恢复确认页是已关闭工单，没有备注输入框，用页面已有的 3 条草稿提醒加 1 条关注冲突（共 4 条）；媒体预览所在的测试夹具没有关注功能和草稿提醒，只能产生 1 条持久提示（内部备注冲突）。定位不依赖数量。

## 已知限制

- 宽度 ≤ 1280 时多数弹窗右侧不足 272，展开列表为浮层，可以盖住弹窗（按确认的方案：「Beside, else popover」）；收起后不遮挡。
- 窗口过矮、弹窗四周都放不下 32×32 胶囊时，弹窗最大高度会临时减小（最多到能在下方放下胶囊），胶囊不再需要时恢复。
- 提示的 DOM 仍挂在打开的弹窗里，只因为弹窗会把页面其余部分设为 inert；定位只看窗口与弹窗矩形。
