## 产品方案A：保留5秒健康重读

按本次明确决定，只有浏览器真实离线或获权业务读取失败/超时使用1s/3s/8s三次预算；预算用尽停止自动重试，超过60s显示陈旧条。只有实时流不可用而完整获权读取成功时，恢复main的单调度器5秒周期，持续重读并等待空位，不显示断开/陈旧条。一次完整读取成功就清除失败时间和次数，不依赖流是否恢复live；手动REST和原READ/UNKNOWN终检不变。没有新增poller。

`wbint-t38-protocol` 的原容量断言已从main `f76fffef7c693ddcee0139b4f6f03bf59376e358`恢复：33号连接的终止503等待原5秒周期、32个已接入连接不受影响、仍允许一次人工REST、空位释放后返回live。仅追加超过12秒仍持续且有界GET及连接条不出现的断言。35A新增真实浏览器读取15秒以上、三个5秒间隔和随后恢复live；单计时器测试覆盖服务端不可用、终止CLOSED、失败后恢复及超时后恢复，分别跨过65秒且预算为0。

本轮健康重读间隔实测5004.5 / 5084.8 / 5056.2ms，12次看板读取均成功、连接条从未打开；故障重试间隔实测1008.2 / 3001.4 / 8001.6ms。见[健康读取回执](receipt-35a-healthy-polling.json)、[65秒调度回执](receipt-35a-healthy-polling-unit.json)、[真实故障回执](receipt-35a-readonly-connection.json)。与main逐行比较确认21条原断言行全部按原顺序保留，见[协议保留证明](checks/option-a-protocol-preservation.json)。
