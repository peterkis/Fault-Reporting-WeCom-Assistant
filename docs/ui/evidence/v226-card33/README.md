## 怎么产生

- **成功 / 进行中**：真实「关注」按钮；进行中由页面拦截器把关注请求延迟 2.5s，200ms 后出现无关闭按钮的进行中提示，随后同一请求完成变为成功。
- **失败 / 结果未确认**：真实内部备注保存，拦截器把保存答复改为 409 冲突（失败，两行说明）；草稿守卫报告原操作待核对（结果未确认）。
- **信息**：同一工单重新载入，内部备注草稿从本浏览器恢复（「恢复状态 · 已恢复当前浏览器的草稿」）。
- **单行**：真实界面里唯一没有用途名也没有标题的提示是恢复弹窗自己的结果；本夹具的草稿恢复不可用，弹窗不会发出命令，到不了这条路径。标题规则（无标题、无用途名时返回空，不再回退成「操作提示」）由 [pc-admin-toast-policy](../../../../tests/pc-admin-toast-policy.test.mts) 单元测试覆盖；截图里的单行一条，是把真实成功提示的 DOM 按组件的单行结构（消息作为唯一的 `.workbench-toast-purpose`，内容加 `.is-single`）改写后，由生产样式表排版，并同样做几何断言（常规字重、主色）。
- **语气截图**：每条提示出现时先在原位做几何与语气断言，再复制它渲染出的 DOM；最后把六份复制按原型顺序放进同一页面的一行静态网格截图。真实界面同时最多显示 3 条，无法让六条同时出现。

## 几何断言（每条可见提示）

色块高度 = 提示高度（±0.5px）；色块宽 52（窄屏 44）；图标 20（窄屏 18）且与色块中心的水平、垂直偏差 ≤ 0.5px；关闭按钮中心与提示中心的垂直偏差 ≤ 0.5px；进行中没有关闭按钮、保留 42px 空位；色块背景等于该语气的 `--tone-*-bg`（在页面内解析），图标为 `CircleCheck` / `Info` / `TriangleAlert` / `CircleX` / `LoaderCircle`。两行说明（失败、结果未确认，高 86）同样成立。32D-T 的避让用例在 4 个宽度 × 抽屉 / 整页 / 弹窗与 1440×560 矮窗口下对所有提示执行同一组断言。

## 阴影取样方法

1. 视口计算样式：`overflow-x/y: visible`、`padding: 0`、背景透明、无阴影、无边框、`max-height: none`。
2. 截取视口外扩 8px 的区域两次：一次显示提示，一次只在这次截图期间把视口设为 `visibility:hidden`。两图相减只剩阴影，背后的文字和控件被抵消。
3. 按阴影色 rgb(15,15,15) 把差值换算为每个像素的阴影不透明度 `(off − on) / (off − 15) × 255`；背景亮度低于 60 的像素（文字笔画、图标）信息不足，跳过。提示本身及其 1px 描边（每条外扩 2px）不计。
4. 断言：提示外侧存在阴影（最大不透明度 ≥ 2，证明没被裁到提示框内）；且每一对相邻行、相邻列上，不透明度跳变超过 3 的位置不超过一半——裁剪边是一条贯穿整行 / 整列的直线，背景文字只造成零散跳变。
5. 结果（receipt-32d-toast.json `shadows`）：抽屉最大不透明度 22.18，最差一列跳变占比 3.6%；整页 20.6 / 0.4%；弹窗 18.06 / 0%。

已知限制：弹窗内的提示仍会遮住弹窗正文的一部分（不遮按钮），沿用 32D-T 规则，本卡不改位置。
