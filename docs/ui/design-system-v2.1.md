### v2.1.1 卡 17 前向收尾（2026-11-03）

本节按用户确认的 3D 布局 + 3B 视图切换 + 3A 筛选样式、列头 B+C 组合，取代下文对应的历史呈现要求；业务口径保持。

- 右侧看板/列表为全圆胶囊，底色 muted、3px 内边距、项高 30px，选中白底 shadow-2。第二层为 260×32 搜索、20px 发丝线、30px 类别/处理人胶囊；生效使用 brand-subtle、`--border-brand-subtle: #BFD3F2`、tone-brand-fg（blue-700），值 600，可单独清除。高级搜索沿原表单和条件，不新增查询。
- 常驻已处理日期「今天 / 近两天 / 近 7 天 / 本月 / 自定义」，默认近两天映射 recent，其余沿 custom civil 日期参数。仅影响已处理列；搜索时不显示。自定义复用原中文日期控件，取消筛选与清除语义保持。≤1100px 日期另行，≤900px 收拢下拉。第二层下间距 16px。

- 卡片更多操作置右上；悬停热度让位，类别列只放类别图标。整卡可拖，保留原菜单的键盘合法表单入口和旧 data 钩子。尺寸复用现有 Token 的值或组合，不引入依赖。

2026-11-03 原型像素复核补充：日期项采用原型的 13px、左右 12px、组内 2px 间隔；自定义应用后持续显示白底、shadow-2、600 与日期范围，手选范围恰与预设相同也仍显示本次自定义选择。双筛选生效时优先省略长类别，处理人短值保留可读宽度；工具栏按实际剩余空间让日期换行，避免1101px等断点边缘把标签压成重叠。≤1100px仍固定换行、≤900px仍收拢，日期不越过工具栏右边界。阶段外环描边 1.6，处理中内半圆半径 3.5；阶段标签左 8 / 右 10px，列头左 10px。看板父容器透明，仅各阶段泳道着色。工作台无副标题页头仅在本页取消空副标题的高度预留，保留共享页头其它页面行为；页签上留 2px 对齐原型。所有尺寸沿现有 Token 或其组合，既有品牌/阶段色、用户明确指定的 tertiary 计数与 Token 阴影不改。

旧节中的色带、概况卡、未分类虚线和小时长文案仅记录 v2.1 原交付，不用于本卡验收。

**v2.0 在「工程规范」层面基本合格，在「体验与美感」层面只完成了一半。** PR #127（`a32f88e`，123 个文件，+2312/−1204）把 Stylelint 违规从 600 条清到 0，裸 hex、`!important`、随意字号圆角全部消失，24 个共享组件就位，`style.css` 从 693 行降到 7 行——「各是各的」问题已经解决。

但新的问题是**过度去色 + 动线未重构**：颜色只剩 6px 圆点，三列、所有卡片、所有按钮长得一样；详情抽屉里看不到「下一步」；会话页消息区被操作区挤到约 200px；缺失数据（「未提供 / 未登记」）在卡片上大量堆积。

v2.1 的方向一句话：**骨架保持 Notion 的安静，把颜色按「阶段 → 紧急 → 类别 → 人」四层有节制地加回来；用 Airbnb 的「一张卡告诉你现在该做什么」重构每个场景的主动线。** 配套高保真原型见第五章。

## 二、为什么「统一了，但还是不好看」

v2.0 解决的是**一致性**，而美感来自**节奏与对比**。现在的界面每个元素都「正确」，但整屏没有焦点。五个具体原因：

1. **对比度只有一档**：所有卡片白底、同阴影、同字重；所有列同灰底。统一不等于均一，一屏至少要有「背景 / 容器 / 内容 / 强调」四个可辨层次，现在只有前三个。
2. **颜色被当成了风险而不是信息**：v2.0 原则「颜色只表达需要行动的信息」被执行成了「尽量不用颜色」。但阶段本身就是行动信息（待受理 = 要有人接），它值得一个足够大的色块，而不是 6px 的点。Notion 自己的看板也会给列头一个彩色胶囊。
3. **噪音比信号多**：合成数据里大量「未提供 / 未登记」按普通元信息显示，占了卡片 1/4 面积。真实环境中群报修的资料常常不全，这个问题会长期存在。
4. **动线上没有「下一步」**：用户打开一张单子或一个会话，第一个问题是「我现在该做什么」。Airbnb 的预订卡、行程卡都把这个答案放在最显眼的位置；现在我们的答案藏在折叠里。
5. **信息按「数据字段」排列，而不是按「任务」排列**：会话页把原始来源、当前来源、主题、接待责任逐字段展开在消息上方，这是「调试视图」的写法，不是「客服工作台」的写法。

所以 v2.1 不推翻 v2.0，而是在它上面加三件事：**有节制的颜色、每个场景一张「下一步」卡、缺失数据的统一收纳**。

## 三、色彩系统 v2.1：四层有节制的颜色

规则是**颜色面积与信息的重要程度成正比**。一张普通卡片仍然是白的；越紧急、越需要行动，颜色面积越大。整屏的「彩色像素」目标占比约 8–12%，现在大约是 1%。

| 层 | 表达什么 | 在哪里用色 | 面积 |
| --- | --- | --- | --- |
| ① 阶段色 | 这张单在哪一阶段 | 看板列头色带（顶部 3px 色条 + 浅色列头底 + 彩色计数胶囊）、抽屉状态胶囊、列表分组行 | 中 |
| ② 紧急色 | 需要立刻处理 | 卡片 1px 色调描边 + 等待时长热度芯片（不用左侧色条，避免「一排彩色竖线」的模板感）；只在超时 / 催单 / 待复核时出现 | 小但强 |
| ③ 类别色 | 什么类型的故障 | 卡片左上 28px 圆角图标瓷砖（网络、打印、业务系统、影像……） | 小但常驻，这是 Airbnb 「类别条」的温度来源 |
| ④ 人物色 | 谁在处理 | 头像稳定哈希色（已有） | 小 |

- v2.1.2 删除看板底板和 `--bg-board` / `--bg-column`；三条 `--lane-*` 泳道直接位于白色页面，各列自然高度。

## 四、分场景交互与动线

每个场景先写「用户来这里的一个问题」，再写如何让界面在第一眼回答它。

### 4.1 团队工作台——「现在最该先处理哪一张？」

**概况条（新增）**：标题下方一行 4 个可点击的指标芯片：`待受理 10`、`超时 2`（红）、`我负责 3`（蓝）、`今日已处理 4`（绿）。点击即为筛选，再点取消。这是用户开班第一眼的「今天的工作量」，也是整屏的第一处色彩焦点。

**看板列**：2026-11-04 用户明确以离线原型01为当前列头基准，06–08为讨论稿。列头为26px阶段胶囊（阶段图形 + 13/600名称），计数在标签外用13px secondary；无顶部色条。保留右侧真实适用的排序菜单。原卡10的3px色条/彩色计数胶囊仅为历史方案，不再作为当前验收目标。待受理仍分「待判断 / 待接单」，组计数、折叠与默认展开合同不变。

卡 10 实施细则以本次任务卡为准：计数胶囊为白色半透明；[设计系统 §6.6](design-system.md#66-看板列-boardcolumn) 记录 2026-11-02 用户确认的排序、过渡统计口径。处理中暂缺状态起始时间时不推算等待；「已超时」暂只计待受理 Ticket 并明确提示。完整热度仍依赖卡 11。

### 4.2 工单详情抽屉——「这张单该怎么往下走？」

**顶栏**：去掉所有图标按钮边框（ghost）；顺序 `↑ ↓ │ ↗ ☆ ⋯ ×`，`↑↓` 旁显示「3 / 10」。

**英雄区**：类别瓷砖 + 编号 → 标题 20/600 → 阶段胶囊（彩色、可点击查看状态变化）+ 子状态 + 等待热度。

**下一步卡（新增，核心改动）**：标题下方一张浅色圆角卡，底色跟随阶段。它用一句话告诉用户当前情况，并给出 1 个主按钮 + 最多 2 个次按钮：

| 状态 | 一句话 | 主按钮 | 次按钮 |
| --- | --- | --- | --- |
| 待接单 | 已等待 1 小时，尚无人领取 | 领取并开始 | 派单给… |
| 已领取 | 周宁已领取，尚未开始 | 开始处理 | 转交 / 退回派单 |
| 处理中 | 周宁处理中 · 40 分钟 | 登记完工 | 挂起等待 / 转交 |
| 等待中 | 等待厂商 · 已 2 小时 · 下次跟进 11-02 10:00 | 恢复处理 | 设置跟进 |
| 待确认 | 已解决，等待报修人确认 | — | 重新打开 |

按钮只显示当前用户有权限的；都没权限时卡片只保留一句话，并写「你当前为只读」。原「处理与协作」折叠里的表单改为点击按钮后就地展开在下一步卡下方。

**属性区**：两列不变；缺失字段收拢成最后一行「未提供：报修人、部门、电话」，已有实际补问入口时才显示对应操作；当前仅有内部等待记录、没有对外补问入口时，不显示「向报修人补问」占位文字。「报修时间」字号与其它值一致（现在偏大）。

**内容区**：页签「动态 / 附件 2 / 会话」，默认动态。描述放在动态第一条（报修人原话气泡）。附件 0 时不显示页签计数。「当前范围的记录已加载完毕」删除。

**备注输入（底部吸附）**：Notion 评论框式单行自增高输入框，左侧当前用户头像，框内左上角「🔒 内部」徽标，右下角发送图标按钮；`Ctrl+Enter` 保存。「重新读取工单动作」移入「⋯」菜单并改名「刷新可用操作」。

### 4.3 会话——「谁在等我回复？我该回什么？」

**列表项固定 3 行**：姓名 14/600 + 科室 12 + 右侧时间；最新一条预览；状态小点「待接待」+ 「3 个主题 · 9 个群」聚合计数 + 右侧未读实心蓝徽标。不再逐个列出群名。等待超过阈值的联系人时间变红。

**中栏重构（核心改动）**：

1. 头部压缩到 56px：头像 + 姓名 + 科室 + 状态胶囊；右侧是主题切换下拉（「护理系统连接超时 ⌄」）和「⋯」。原始来源、当前来源移到右栏。
2. 消息区占满剩余高度。报修人消息左侧灰气泡、工程师右侧品牌浅蓝气泡、内部备注右侧浅黄气泡带🔒、系统事件居中灰色小字。按日分隔；渠道「Bot 私聊」不再写在每条气泡下，只在渠道切换时插入一条分隔。
3. **接待横幅**：未接待时，输入框上方是一条浅黄横幅「宋岚已等待 12 分钟，尚无人接待」+ primary「我来接待」+ ghost「请求人工接管」。接待后横幅消失，输入框可用。符合「先接待再回复」的业务合同。
4. **输入区**：框内顶部分段「回复报修人 / 内部备注」；切到内部备注时整个输入框变浅黄（防止把内部内容发给报修人，这是安全性设计）；发送按钮 primary 在右下，`Ctrl+Enter` 发送。「发给本服务主题的原报修人…」说明改为框内占位符。

**右栏**：关联工单以迷你 TicketCard 呈现（与看板同一组件），点击在当前页打开抽屉；下方「报修人历史 3」、「来源」折叠。

### 4.4 通知异常——「有哪些通知没送到？」

- 有数据：表格列为 结果（danger/attention Tag）· 关联工单 · 接收人 · 渠道 · 时间 · 操作（核对）。顶部用一条 danger InlineAlert 写「3 条通知发送失败，报修人可能不知道进展」。

- 副标题改为「发送失败或结果待核对的通知。查看不会触发重发。」。

### 4.5 全局

- **顶栏**：「人工协作 / 只读」从顶栏中部移到左下账号区（姓名下的角色小字）；顶栏右侧只留连接状态点和设置。所有页面都显示面包屑，包括工作台。
