# 医小修联系人会话界面

沿[原视觉规范](yixiaoxiu-ui-design-spec.md)的外壳、字体、Token 和路由实现。新收件箱默认关闭；[接口和回退](../api/workbench/conversation-inbox.md)、[本地验收记录](../../plans/admin-workbench-integration/execution/conversation-inbox-v1.md)分别记录当前行为与实际证据。

宽工作区为约300px联系人、聊天、约320px关联摘要三栏；以工作区实际可用宽度决定布局。空间不足时关联摘要收为“查看关联事项与来源”；窄屏按联系人与聊天分步查看，保留返回入口。当前选择始终是明确 Session，重读和排序不会自动切人或主题。联系人列表保留队列、原始来源、安全群引用、搜索和签名分页。

聊天顶部显示服务主题、原始来源、当前窗口、沟通接待人和“发送到本人 Bot 私聊”。同人不同问题分别选择，可靠群转私聊只提示补充。普通回复发送到本人私聊；群原始消息、私聊回复、人工、规则自动、内部备注和服务事件有独立标签。当前关联事项为空时使用“暂无可展示的关联事项”，不推断是否建单或是否有无权事项。

“回复用户/内部备注”复用原 Composer 和各自草稿/原UUID核对。文本最多2000字符；Enter提交，Shift+Enter换行，IME组合期间Enter不提交。备注不外发；结果未知时保留原用途、正文、UUID和版本，只由明确操作核对。

首次最近50条，按需最多400条。加载旧材料保留滚动锚点；在上方阅读时新消息仅提示，靠近底部才跟随。精确 Message ID 关联投递状态，正式投影替换已提交待同步提示；状态未取得时明确“尚未读取”。渠道确认与用户已读分开。媒体未保存/不可读时保留占位，受控下载仍在原附件入口。

只复用一个 Realtime controller、EventSource 和原5秒失败回退。SSE提示只触发获权REST重读；隐藏、离线、账号/授权修订变化沿原epoch和AbortSignal处理。个人未读只按原可见材料观察推进本人Cursor，不清团队待跟进。输入、未决命令和当前选择不能被实时提示覆盖。

离开主题后不保留非活动聊天查询缓存；返回主题时先完成当前授权读取。收到403/404立即撤下聊天材料。草稿和未决命令继续沿既有主体、用途及失权清理规则处理。

个人Cursor的投递结果未知时，下次真实前台观察先读取本人当前Cursor；原坐标尚未被当前事实确认前只读核对。此状态跨材料重读保留，避免自动生成新UUID重复写入，也不因一次ACK丢失永久停止获权阅读核对。
