## 判定口径

| 状态 | 含义 |
| --- | --- |
| 通过 | 已有对应的真实租户或本机 Windows 验收结论，并列出证据。 |
| 不通过（降级） | 已验证当前 SDK/租户不可依赖；后续产品必须采用列出的替代路径。 |
| 未验证 | 没有足够的真实租户结论；不得在设计、代码或验收中表述为已支持。 |

接口 ACK 只表示企业微信接受请求。凡涉及显示、通知、打开或播放的“通过”结论，均以对应证据中已记录的客户端人工观察为前提。

## 冻结结论与产品降级

| 能力域 | 结论 | 冻结约束或降级方案 | 证据 |
| --- | --- | --- | --- |
| 接入与连接 | 通过，单连接限制已确认 | 保持公网出站 WSS 为主接入；每个机器人同一时间只支持一个有效长连接。新连接完成订阅后会踢掉旧连接，服务端主动断开旧连接；高可用只能采用顺序主备切换，不得并发建立有效连接。 | G0-001、G0-002、G0-007、`evidence/g0-008-project-owner-confirmations.md`，ADR-0001 |
| SDK 与运行时 | 通过 | 使用精确版本 `@wecom/aibot-node-sdk@1.0.6`；SDK、Node 运行时、进程管理或网络策略变更后，先重做关联 Contract Test 和真实租户复验。 | G0-002、G0-007、`package.json` |
| 入站文本触发 | 通过，有限范围 | Phase 1 如需群入口，必须要求用户 @机器人；不得依赖群内未 @ 文本。企业微信 Frame 仅在 WeCom Adapter 内归一化，不能作为业务模型。 | G0-003、ADR-0007 |
| 入站重复与重放 | 未验证为“不会重放” | G0 仅观察到两条重复发送具有不同 `msgid`，且稳定窗口无同一消息重放；Phase 1 必须自身实现持久化幂等，不得假定平台去重。 | G0-003、G0-007 |
| 入站媒体 | 通过，有限范围 | 图片/文件/语音/视频按各自真实 Frame 处理；媒体仅在内存下载/AES 解密，日志与证据不得保存 URL、AES Key、原始内容或原始文件名。Magic/MIME 优先于扩展名。 | G0-004 |
| 回调绑定回复 | 通过，有限范围 | 可采用已验证的欢迎语、流式、Markdown、文件、图片、语音和基础视频回复。反馈事件后的空包响应不可依赖。 | G0-006A |
| 出站临时素材 | 通过（回复侧；主动侧显示可见性已确认） | 所有出站媒体使用 `init → chunk → finish → media_id` 的 Adapter 临时租约路径。项目负责人已确认主动媒体投递客户端显示可见；该确认不扩展为类型逐项播放、容量、超时、重试或限流结论。 | G0-006A、`evidence/g0-008-project-owner-confirmations.md`、`docs/18_wecom_temporary_media_constraints.md` |
| 视频容量 | 当前环境单样本通过 | 精确 10 MiB 串行分片回传、显示和播放均已确认；3.92 MiB 高层并发超时不再作为硬上限。自动视频回复默认上限仍保持 1 MiB，超过时继续走明确提示/受控替代，禁止静默转码或公开链接，直至项目负责人确认容量策略。 | G0-OPEN-003、G0-006A、`docs/18_wecom_temporary_media_constraints.md` |
| 主动通知 | 通过，有限范围 | 单聊可用于个人进度；群消息仅用于低敏感公共信息。重要个人通知不得依赖群 @，而须通过后续 Outbox 的单聊投递与结果审计。 | G0-005、ADR-0006 |
| 模板卡片 | 通过，有限范围 | 卡片只作交互展示；按钮事件按真实嵌套结构归一化。更新必须在事件后 5 秒内发起，否则走文本/状态查询等降级，不能让业务事实依赖卡片更新成功。 | G0-006 |
| 群内 @ 提醒 | 不通过（降级） | 当前已测 Markdown 标记、`text.mentioned_list`、纯文本回调回复和流式回调回复均不能形成可靠原生 @ 提醒；改用单聊或低敏感群广播。 | G0-005、G0-006 |
| 稳定性与故障恢复 | 通过，单活范围 | 4 小时 30 分钟独立浸泡及规定恢复场景均已完成。消息重放、容量和恢复指标只描述已测环境，不构成提供方永久 SLO。 | G0-007、ADR-0008 |
