# P2-G2 Directory boundary contract

Scope: continuing gap-repair authorization; D12-019–026. No database migration, Person registry, hospital directory connection or P3 identity integration.

`createReporterDirectoryPort` keeps its existing injected resolver. Its default deadline is 500 ms; an explicitly supplied deadline must be an integer from 1 to 2000 ms. Timeout returns `DEFERRED` with an empty snapshot and aborts the supplied AbortSignal. At most one resolver call may remain in flight per port. If an adapter ignores cancellation, subsequent requests defer without starting additional unresolved calls. The port does not hold a PostgreSQL transaction while waiting. No provider error text is copied into the snapshot.

An injected trusted Directory Simulator may return `RESOLVED` with `snapshot.source=WECOM_DIRECTORY`, a nonempty `snapshot.version`, and `snapshot.account_status=INACTIVE`. This is a directory-account assertion, not a Person merge or Ticket authorization. The current Intake is routed to existing Manual Review with reason `DIRECTORY_ACCOUNT_INACTIVE`; explicit fault recognition still recommends and executes minimal Ticket creation. The original Inbox and directory snapshot remain persisted. The persisted decision records review reason, snapshot hash and the bounded directory-account assertion (source, version, account_status, valid_at, fetched_at), never the full directory payload. Authorized Manual Review detail exposes this assertion to the reviewer; ordinary Journey decision projection strips it and retains only reason/hash. A later INACTIVE assertion therefore remains auditable without replacing the original report snapshot. Identical message-window replay keeps its committed decision.

D12-019 verifies only directory resolution and report-time snapshot. Reporter HMAC is not `SYSTEM_PERSON_ID`; the latter is absent from this P2 implementation. D12-021 preserves all membership roles without selecting an arbitrary primary department. D12-022 keeps directory department separate from reported occurrence location. D12-025 verifies immutable prior Journey snapshot and a later Journey's newly fetched snapshot; it does not claim a shared current Person profile. D12-026 verifies the actual ordinary HTTP projection excludes the snapshot. D12-023 remains a P3-only contract requirement and cannot be counted as a successful runtime identity reconciliation.
