# P2-G2 prepared-candidate guard

The CLI, process-cluster constructor/start and every dedicated child role now use the same prepared-candidate check before starting database/listener/SDK work in live mode. This does not authorize or perform a live run.

The checker requires numeric full-regression counts, actual passing TAP rows and matching totals, no failing rows, a hashed full-run record with the same candidate and complete normalized test-file inventory, all 37 scenario IDs mapped to actual passing test names, and two independent review axes. Review-source JSON must agree with its summary on candidate, axis, reviewer, verdict and unresolved findings. All evidence references are bounded files inside `evidence/`, with hashes checked. This is local evidence integrity checking, not cryptographic authentication of reviewer identity.

The final preparation report must provide `source_evidence.regression_run`, `source_evidence.scenario_matrix`, and `source_evidence.independent_review` as `{path,sha256}` references. The matrix contains `candidate_fingerprint` and `scenarios[{scenario_id,preparation_status:"VERIFIED",test_names}]`. The review summary contains `candidate_fingerprint` and two `reviews[{axis,reviewer,verdict,unresolved_findings,source}]`. Each source is JSON with the same fields plus `findings`, all resolved. Actual final review records are still pending; unit fixtures exist only in disposable temporary directories.
