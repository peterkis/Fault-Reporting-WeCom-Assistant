## 所有任务共用的执行合同

1. 实施开始前确认 cwd、HEAD／branch、HTTPS remote、工作区／index、可写路径和当前活动 selection。来源群后继增量、用户的 AGENTS／医小修 UI 文档修改及其他附件保留；只修改领取任务的范围。
2. 先确定 METHOD＋PATH＋宿主、输入／输出 Schema、版本类型、认证／权限、错误码和实际 HTTP 装配，再写依赖它的前端。新增路径未挂载前始终标为计划；完成后同步 `docs/api` 模块、索引、conventions／design-and-gaps，不让两份合同各自演化。
3. W Cookie 命令执行当前认证、CSRF、Origin、对象／目标授权；UUID Idempotency-Key 与 body 一致，版本 Header 与 body 一致。复合命令逐对象检查，在同一事务内写责任、状态、追加事件与可靠通知承诺。失败全部回滚，重放前重新验权。
4. 旧状态与角色规则存在差异时，按 Accepted ADR 修订当前合同与实现文档，保留兼容模式、默认关闭状态及旧证据；不改受保护证据／认证器／候选指纹，禁止直接 SQL 改状态或另建 Ticket Core。
5. 数据库变更采用现有单库迁移流程，实施时重新分配唯一编号段；已用 037 不重复编号，不在固定历史迁移列表插入后继业务迁移。优先最小字段／关系和必要索引，不写历史 Ticket 导入或批量回填产品线。
6. 每项新增功能以显式宿主配置／持久功能开关控制，默认 false；合同确定名称、读／写／外发依赖。关闭新入口可回到旧获权入口；已提交事实保留。数据库扩展采用向前兼容，不用删除表作为普通回滚；不可兼容时先停相关写入并独立评审。
7. App/API/SSE、Worker、Gateway、池和并发沿[资源基线](README.md)；不引入新服务、BFF、消息中间件或验证平台。列表／子查询有上限、游标、授权、稳定排序；不按卡片扇出所有消息／投递／目录请求。
8. 按风险在已有 public HTTP／Port／隔离 PG seam 验证，不写只镜像实现的测试。普通 PR 跑当前严格类型／负向 canary、一次最终构建、制品核对、相关业务／工具／必要浏览器测试及自有资源清理。不要逐任务重复 full/certify；保护流程按既有 workflow 单独执行。
9. 每任务新证据建议存于 `evidence/admin-workbench-integration/<task-id>-<run-id>.*`，记录实际 HEAD、工作区／候选关联、环境、命令、结果、截图、资源关闭和 NOT_RUN 项，不重写旧报告。更新本表及对应交接；若拆单独任务文件，同步状态，避免两份 Backlog 不一致。
10. 提交结果未知保留同一命令 ID／原 payload；可核对重放不能改版本冒充原命令。Query 只存服务端事实，草稿与 UI 状态独立；401／失权停止显示并清缓存／草稿。成功后重读当前授权事实，不能从点击或动画推导提交成功。

## WBINT-01：命令上下文、提交与草稿恢复基础

- **负责范围**：`web/admin-workbench/src/api/`、独立命令／草稿模块、现有 Router／Query／UI store；后端仅受授权命令上下文查询和必要草稿协议；合同在 `contracts/`。
- **输入**：00 已冻结的分域版本与权限模型，现有 bootstrap／board／detail。读展示 DTO 不包含所需全部版本，不从缺失字段猜默认值。
- **输出／HTTP**：有界 command-context（候选入口见[映射](capability-map.md)）提供真实 actions、版本、材料修订和目标引用；类型解码从 unknown 开始。提供提交／提交中／已提交／版本冲突／拒绝／结果未知状态和原命令核对；不对非幂等意图自动换 UUID 重试。
- **草稿合同**：账号＋浏览器＋kind/id＋表单用途隔离，最长24小时，恢复前验权；保留用户内容和原版本但要求冲突后明确重新提交。提交成功、丢弃、退出／失权清理；未知结果先保留原命令恢复元数据核对。具体存储方案必须满足误关标签恢复、过期清理和隐私，不能默认把敏感原文／身份／Cookie／CSRF 明文放 localStorage；可评估按浏览器隔离的认证短期服务端草稿，不提供跨设备同步。方案在本任务合同中定稿。
- **数据库／开关**：command-context 优先无 DB 变更；仅当安全草稿方案确实需要时增加有 TTL、按主体／浏览器隔离的最小结构。命令和恢复配置默认 false，关闭不删除已提交业务；停止恢复访问并按合同清理到期草稿。
- **验证／证据**：A01：401/403、角色撤销、跨账号／事项串草稿、刷新／误关恢复、24h清理、JSON／版本异常、请求超时／成功响应丢失、原 UUID 重放、payload 改动冲突；必要真 HTTP＋bundle 浏览器验证。
- **资源**：复用 App／池；限制每浏览器草稿数、单草稿大小和恢复频率，合同须给实数上限，不无限增长。无真实身份／外部调用。

## WBINT-02：轮次、责任与一步处理

- **负责范围**：单一 Ticket Core 的 command/query Port、既有 facade／状态动作／事务、Conversation responsibility 边界、React 详情动作和目标选择；不复制第二套状态／所有权。
- **输入**：01 上下文及原命令恢复，03 将消费的轮次／事件合同。首次处理与每次重开定义轮次；交接／等待／退回不新增轮次。
- **输出／HTTP**：take-and-start、assign、takeover、unassign、return-to-dispatch；扩展已有 accept／transfer／reopen 的合法目标语义并保留次级“先接单”。未开始撤派与已开始停止退回分开，冻结每种 old/new status、回到待安排和再次承接规则。
- **原子／权限**：只对获权可见且具备相应业务权限的对象操作；跨团队人＋有效组一起交接。明确会话集合，逐一同源／主题／身份／授权／版本校验；默认承接，可保留原沟通人，无会话走 Ticket-only。不能允许前端提交任意 session ID。两个同事竞争只有合法版本成功。
- **数据库／开关**：在现有核心增加最小轮次／责任历史依据及必要约束／索引；追加事件，不覆盖过去责任。新动作默认 false；停止入口后保持现有合法查询和关闭模式，不还原已交接责任。
- **前端**：按 actions 显示一步处理、先接单、派同事／跨组接管、等待／恢复、撤派／停止退回；目标有多组时选择，显示真实前后责任。取消工单沿旧合法条件与独立确认，不改名成退回。
- **验证／证据／资源**：A02，状态矩阵、并发／同 UUID 竞态、目标人员离组、权限撤销、多会话误关联、任一写失败全回滚、重新承接及轮次不膨胀；隔离 PG＋HTTP。事务／池复用，实际会话集合上限在合同冻结，不无限批量接管。

## WBINT-03：完工关闭、代办关闭与责任链

- **负责范围**：Ticket 完工应用用例／安全历史投影、合同及 React 完工／交接视图；保留 Reporter 与外发投影边界。
- **输入**：02 处理轮次、责任及合法版本。根据现有状态机冻结完工可执行状态，等待中的恢复必须是合法显式动作／同事务事件，不能任意写 CLOSED。
- **输出／HTTP**：complete、takeover-and-complete、assignment-history。内部处理过程必填，对外简短结果单独确认，不默认复制内部全文；一次事务记录 STAFF_COMPLETED 关闭依据、操作者／轮次／时间、追加事件与可恢复通知承诺。代办同时交接责任并关闭，全部成功或全部失败。
- **前端**：按钮／完工表单／处理链替代旧多步确认；提供首次承接和每次前后人／组／沟通责任、操作者和轮次。旧 RESOLVED 保留待确认标签，不显示为 Reporter 已确认。
- **数据库／Schema**：当前核心的轮次结束／关闭依据与内外记录最小扩展；历史查询有界分页、按当前授权裁剪。新增事件与 DTO 同步 Reporter 安全投影和通知消费合同。
- **验证／证据**：A03：两人并发关闭、接管事务失败、原命令响应丢失、重放仅一条完工事实／每路一条意图、内部文案不能进入群／Reporter、已终态禁止再次完工；PG＋HTTP＋生产 bundle 表单行为。
- **开关／关闭／资源**：默认 false；关闭新完工入口，保留旧只读与历史事实。未知外发不回滚关闭；通过现有投影检查点／Outbox恢复，不加发送进程。

## WBINT-04：复核到处理与受控报修资料

- **负责范围**：现有 Manual Review／Intake／Journey 应用用例、材料与附件安全入口；React 同事项复核／资料区。可分两个小 PR：既有复核读取／resolve 与复合处理／受控附件。
- **输入**：02 的最小 Ticket／承接事务、Review 当前 row_version／材料修订与支持的结论；沿用现有八类 resolution，不能把所有不明材料建故障单。
