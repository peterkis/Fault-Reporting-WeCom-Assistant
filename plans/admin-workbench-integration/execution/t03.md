## 实施前冻结的合同

输入为当前服务器核验的内部 `principal_id`、`kind=ticket`、Ticket UUID、`purpose=internal-note`、受控备注文本和可选不可变 `P2016InternalNoteCommand`。输出为明确的正在保存／已保存恢复副本／不可恢复／过期状态，或经重新验权后恢复的输入与原命令。Query 继续只保存服务器事实；Zustand 只保存临时 UI。无服务器草稿服务、无数据库迁移、无新依赖、无第二 Ticket 事实源。

新增显式宿主选项 `workbenchDraftRecoveryEnabled:boolean=false`；生命周期 bootstrap 返回 `draft_recovery_enabled:boolean`，只有内部备注同时启用才有效。默认关闭路径不打开 IndexedDB、读写草稿或新增 SQL。关闭新入口不改变旧 notes、已提交事件／receipt、业务 Flag 或已验证 Gate。关闭时遗留密文不恢复，下一次启用遵循固定到期；显式退出仍清本应用已知主体草稿。

仅当前 origin／浏览器 profile 的原生 IndexedDB `wecom-workbench-drafts-v1`，schema 1。范围是 `[principal_id,kind,id,purpose]`；这些内部 opaque UUID 和用途、schema、首存／到期 epoch、随机 revision、IV 是明文元数据。备注和完整原命令只存 AES-GCM-256 密文；每次新 96-bit IV、128-bit tag，AAD 绑定上述 scope、schema、时间、revision。每条使用不可导出 CryptoKey，权限仅 encrypt／decrypt；不存 Cookie、CSRF、OAuth、姓名、外部原始标识、标题或角色。此方案不声称防同源 XSS／browser-profile 访问，也不声称磁盘加密／硬件隔离／删除后零化。

固定最大期限：首次实际提交恢复副本时 `expires_at=first_saved_at+86400000`，后续保存不续期；到期不再展示，活动页清理，初始化／读写再清理过期数据和密钥。浏览器关闭期间不能主动物理清理；残留为密文，应用拒绝恢复过期记录。浏览器可清除 best-effort 存储，不保证副本一定可用。最长20条／origin；每条 UTF-8 plaintext JSON ≤16384 bytes，备注仍 ≤2000 UTF-16 字符。最多每500ms一次常规保存，连续输入最多500ms开始落盘；强制提交快照及明确丢弃／成功／退出／失权可立即交易。无静默淘汰有效条目或 unknown；超限／IDB或crypto不可用保留当前输入并显示未保存，无明文降级。

恢复先通过全新 bootstrap 确认 principal，再通过真实 `GET /api/tickets/{id}` 确认对象可读与当前 add-note；不使用缓存角色猜测。账号／事项／用途隔离；恢复请求取消与编辑 generation fence 防迟到响应覆盖输入，detail刷新／409不覆盖内容。仅失写动作但仍可读的 pending 原命令可核对已提交 receipt，禁止新提交；普通未提交草稿清理。网络／503不是失权。

IDB短 readwrite transaction 在 crypto 完成后再核对单一持久失效 epoch 和当前记录 revision；purge 增 epoch，fence 各标签尚未完成的旧保存／解密。跨标签信号只含清理范围／原因，无正文／凭据，交易为权威；他事项已保存副本不被局部清理。成功删除必须匹配原持久 revision，不能清较新版本。卸载只取消回调／请求，不删除已保存副本。未完成保存时保持导航保护；有成功 durable 快照后未知结果可以导航，重新进入核对同一原命令。

启用恢复时，POST 前必须先成功提交不可变原 UUID／expected_version／payload 密文；失败阻止本次 POST，明确无法保证恢复。unknown 只允许显式重放相同原命令，fresh CSRF仅用于当前 HTTP Header；不能自动换 UUID／版本、trim或自动发送。已知成功／主动丢弃／真实退出／可信401与会话403／对象403或404／过期清对应数据。到期丢失payload后本地不能继续用原 POST核对，不代表服务器未提交；提示人工查看最新工单事实，禁止到期自动重发。资源沿单App／Worker／Gateway、SSE32、池≤8；不新增进程、Worker或网络依赖。

200闭合结果共三种，必含 `client_command_id:UUID,ticket_id:UUID,state`：`COMMITTED` 带既有安全 `result`（ok／ticket_id／ticket_version／ticket_event_id／control_event_id=null／replayed=true）；`FAILED` 带稳定 `error:{code,retryable:false}`；`UNKNOWN` 不带result/error。无收据、STARTED、错目标／错用途／他主体UUID均为UNKNOWN，不能推断未提交；身份401／对象403或404沿既有授权清理，503／网络失败不收口UNKNOWN。不返回正文、payload、hash或私有身份。新专用提交的 `receipt.command_type=WORKBENCH_INTERNAL_NOTE` 由HTTP服务器指定，客户端不得注入；现Hash与旧行／旧重放保持原语义，旧或legacy add-note仅不能从此新只读用途入口核对。

独立操作记录仅保存内部opaque principal／Ticket／用途／原UUID／创建时间，最多20条／origin，每条≤512 bytes，不含正文、payload、Cookie、CSRF、姓名或外部ID。与24h草稿不同，未收口操作标识可保留到服务器明确终态、退出或可信失权；不得因配额静默驱逐UNKNOWN。24h或主动丢弃只清敏感内容和密钥，仍有未核对操作时界面保持停止新UUID、仅提供只读核对。COMMITTED/FAILED才按真实终态收口；普通“忘记”不能绕过停止线。退出／失权清理后重新进入读取当前服务器事实，不推断原操作失败或自动复建／重发旧内容。
