# 分阶段路线图

- 基线日期：2026-08-20
- 当前阶段：G0

## 总体顺序

```text
Gate 0 企业微信能力验证
→ P1 无AI可靠受理
→ P2 工单处理闭环
→ P3 媒体与OCR
→ P4 AI影子分诊
→ P5 公共故障和数据运营
→ P6 试点与推广决策
```

## 阶段总览

| 阶段 | 名称 | 目标 | 周期 | 退出条件摘要 |
|---|---|---|---|---|
| G0 | 企业微信 WebSocket 能力验证 | 用贵院真实租户冻结群聊、图片、主动推送、卡片、重连和单活能力，不写完整业务。 | 2-3天 | 24小时稳定运行；能力矩阵完成；SDK版本和连接策略ADR冻结 |
| P1 | 可靠受理与首次工单 | 在无AI条件下实现消息不丢、不重、自动创建现有Tickets工单并返回工单号。 | 1-2周 | 明确报修漏单为0；重复建单为0；AI关闭E2E通过 |
| P2 | 工单处理闭环与个人通知 | 完成真实状态机、工程师H5、补充信息、解决确认、重开和单聊进度通知。 | 2周 | 接单到关闭全链路通过；状态语义真实；并发操作不回退 |
| P3 | 媒体与OCR | 安全接收截图，私有存储，OCR提取错误文本，纯图片也不漏单。 | 1-2周 | 图片E2E通过；OCR失败不影响工单；敏感数据不进入普通日志 |
| P4 | AI影子分诊 | 建立规则、系统目录、小模型结构化建议、人工修正和评估体系，不直接自动路由。 | 2周 | Schema通过率和分类指标可测；人工修正留痕；AI关闭可回滚 |
| P5 | 公共故障与数据运营 | 建立Incident、多申报人订阅、监控信号关联和月度指标。 | 1-2周 | Incident人工确认闭环；错误关联可解除；首份月报可生成 |
| P6 | 试点上线与全院推广决策 | 完成试点、培训、性能与灾备演练、合规检查和全院推广Go/No-Go。 | 2-4周试点 | 试点评审完成；问题清单关闭或接受；全院推广决策 |

## 阶段纪律

1. 不得跳过 Gate 0。
2. P1 和 P2 的核心闭环不依赖 AI。
3. OCR 完成前，图片失败必须有文字补充降级。
4. AI 在 P4 先影子运行，默认不自动路由。
5. Incident 在 P5 默认人工确认。
6. P6 通过前不全院推广。

## 关键决策点

| 决策点 | 决策问题 | 依据 |
|---|---|---|
| G0-D1 | 群聊是否必须 @ 机器人 | 真实租户 PoC |
| G0-D2 | 群内图片/mixed 是否可用 | 真实 Frame 和解密测试 |
| G0-D3 | 主动群消息和提醒效果 | 用户端实测 |
| P1-D1 | Tickets 不可用时临时回执文案 | 业务与临床风险 |
| P2-D1 | 自动关闭 24h/48h | 服务目录与管理要求 |
| P4-D1 | 是否启用自动路由 | 精确率、风险和审批 |
| P5-D1 | 是否启用自动 Incident 关联 | Precision≥99% 和可回滚 |
| P6-D1 | 是否全院推广 | 试点指标、合规和运维能力 |
