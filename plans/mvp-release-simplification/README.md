## 策略与实施约定

使用 [testing-policy.json](../testing-policy.json) 维护路径→profile→selection 与少量历史专用理由；入口、host、flags、资源元数据唯一来源仍为 [test-routing.json](../typescript-migration/test-routing.json)。[pr-plan.mts](../../tools/ts-migration/pr-plan.mts) 使用 Node 内置能力，真实 Git NUL 差异包含新增/删除/改名双方及中文路径；多模块取并集去重，非法 base/profile/入口/空业务集合失败，未知路径回退较宽首版集合。

| 影响 | 默认策略 |
| --- | --- |
| 普通文档/记录/截图 | 文档链接及指令检查；无 PG/浏览器/媒体依赖/应用构建 |
| AGENTS、工作流、路由、验证策略及工具 | 策略/相关工具、strict、一次应用构建、小规模既有贯通 |
| PC / H5 | 各自代表主链及直接风险；PC 不默认混入 H5/Incident，H5 不默认原生桌面 |
| 工单核心、身份、事务、通知 | 服务/HTTP/PG、授权/幂等/隔离/UNKNOWN 和必要浏览器 |
| SQL、锁文件、共享装配或未知生产路径 | 扩大到当前首版相关组合 |
| 桌面认证、下载、导航、打包边界 | 追加既有 Windows 原生验证 |

应用构建第一版统一保留。构建后通过 `runSelection` API 执行并集；不调用会再次构建的 run-tests CLI，不放宽制品验证。资源从所选入口推导，构建/工具/原生额外需求显式声明。未选择是 NOT_SELECTED，不是 PASS。

CI 保留 `typescript-merge-check` 稳定汇总；计划、文档/无库/有库执行及必要 Windows 的实际结果必须匹配计划。所选 job 失败、取消、跳过、未完成均拒绝。汇总使用 `always()` + `needs`，依据 [GitHub 官方说明](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks)。手动 full/certify 与轻量 evidence-history 保留；两个 SS009 历史 PR 专用 workflow 不作为减负重点。

## 测试生命周期

当前必需保护首版底线和本次直接风险；按需扩展用于仍使用的增强功能；历史专用用于旧流程/布局/候选；后续可物理移除须逐项处理替代、路由、旧别名和消费者。本 PR 只分类少量代表，不删除旧入口/注册保护/冻结证据。具体路径、原风险、适用性及替代或退出原因只写在策略文件，避免重复台账。

新策略测试验证漏检风险：文档无资源、前端隔离、核心扩展、锁文件/共享构建、重命名/删除/中文、多模块去重、未知路径、坏 base/profile/入口/空集合、汇总异常、历史分类及现有源码/制品漂移拒绝。使用受控样本和临时 Git fixture，不创建试验远端 PR。

## 验证、证据与收口

普通交付记录改动、实际验证、结果/未执行及原因、已知问题、回退；按影响补合同/Schema/数据库/安全/资源/flags/Issue。保留被测候选、环境、FAIL/取消/NOT_RUN、发布与受保护证据；日常 CI 原件沿既有 14 天保留，不逐文件人工复核、不复制整套依赖/工作树/数据库到多份报告。资源只清理自有、停用且可重建部分。

适用正式命令：一次 `npm run migration:build`，`node .build/tools/gate.mjs types`，新策略测试、相关工具检查、`check-agent-docs.mjs`、`verify-artifact.mjs`；业务子集构建后用 API。扩大验证需具体风险、缺口和停止条件，通过即停止。历史 task/full/certify 不自动增加义务。实际本地、模拟计划与 GitHub 耗时分别报告；以已有 CI 对照，不重跑旧重型 CI。

验收：文档一致；业务/配置边界不变；文档零应用资源；前端有界选择；核心扩大；每执行环境一次正式应用构建；汇总拒绝意外跳过；历史分类有理由且原件保留；strict/构建/策略/相关工具/制品检查通过。PR 提供数量、资源、结果与限制，不声称 full/certify/生产就绪。最终以规则/工具可审查、相关验证通过和独立 PR 为止，不自动合并。
