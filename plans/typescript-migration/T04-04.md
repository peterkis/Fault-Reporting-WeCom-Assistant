## 类型与行为

Adapter 由 unknown 经原校验输出可判别结果，复用 Inbox 归一化消息结构。Intake 明确消息 ID、事务、selector 的 null／禁止复用／指定候选、聚合结果和真实 SQL Row。Access 明确角色、权限、JSON 边界、公共视图及 HTTP 注入端口。

三个目标及 Inbox、Ticket processor、Closure 支持模块经类型擦除后的 AST 与基线一致。默认值、SQL、事务、时间、哈希、错误码、认证主体覆盖请求体以及内部备注可见性均保持原行为。ESNext.String 只提供 Node24 已有 isWellFormed 的标准声明，target 和依赖版本保持原值。

本地双轴审查指出 HTTP 命令过早类型化及 Pool 可误传事务两个问题，已增加负向类型样例并做无运行时变化的修补；后继提交仍须复核。

必要支持范围见 [回执](receipts/T04-04.json)。类型测试在 Adapter→Inbox、Intake→Ticket／Lifecycle／Operational、Access→Action／HTTP 的公共组合边界建立 RED→GREEN。HTTP 兼容回归使用真实隔离 PostgreSQL 和真实 Action service，检查非法 JSON、请求上限、primitive JSON 及主体覆盖。
