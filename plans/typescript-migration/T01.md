# T01 — strict compiler and non-activated shadow artifact

Base: `162ffe7651c97329ace63532bd1f9739cf03550a` (merged T00, PR #24).
This stage adds tooling and an isolated canary; no existing production MJS is renamed, no old npm command is redirected, and no service is started. T02 owns complete test routing and declaration linkage. Its future dependent PR must not claim T01 was merged when it was only reviewed.

Root development dependencies are TypeScript **5.9.3**, `@types/node` **24.19.0**, `@types/pg` **8.23.1**. A read-only dependency preflight queried the real registry and installed with exact pins and lifecycle scripts disabled. ## Actual execution

```text
npm run migration:typecheck
npm run migration:type-tests
npm run migration:gate
node --test --test-reporter=tap .build/tools/tooling.test.mjs
npm run migration:verify-artifact
```

The bootstrap MTS uses Node24's erasable syntax only to invoke the locked compiler. This is not a type-check substitute: it validates the tools emit location before invoking tsc; all tools themselves are then strictly checked. It invalidates previous outputs before rebuilding tools. Consequently `migration:typecheck`/`type-tests` deliberately invalidate an old runtime; run `migration:gate` or `migration:build` afterwards before `migration:test`.

Four explicit configurations separate tools, migration implementations and negative type tests. strict, exact optional properties, unchecked indexed access, unknown catch values, NodeNext and noEmitOnError are required; an empty/excluded program, noCheck or a disabled strict sub-option is rejected. The implementation roots are checked against the actual workspace list, not merely tsc's exit code. Legacy `allowJs/checkJs=false` files are counted as **unchecked**, not typed.

## Build contract

- `.build/.migration-owner` protects the controlled output root; an existing unowned directory or any encountered output symlink fails before deletion.
- `.build/tools` contains compiled build tools; `.build/emit` receives compiler output; `.build/runtime` is the only shadow application graph.
- A typed `.mts` emits `.mjs` at the same logical relative address. Existing MJS is copied byte-for-byte. A same-name MTS/MJS collision fails.
- `resources.json` lists reviewed contracts, synthetic fixture/config resources, SQL and existing static UI files. Git/history/Evidence, real environments, node_modules, keys and the separate frontend prototype are not copied.
- Clean/compile/resource failures remove successful runtime markers. No source fallback, source shim, dual implementation or old-artifact retry exists.
- `build-manifest.json` binds source head/tree/dirty flag, compiler, file inputs, type/legacy accounting and every output digest. `.build/artifact-proof.json` is the outer manifest digest. An external verifier can pass a previously retained digest as its argument. Editing the manifest alone, any source/config/lock/resource, any output, or adding an undeclared output is rejected.
- Two clean builds of the same inputs must produce identical logical files and manifest. Source maps contain relative paths and inline code, not machine-specific source directories.

Artifacts are developer test artifacts (`STAGED_NOT_ACTIVATED`), not approved deployment packages. Runtime dependencies resolve from the locked developer install; independent production packaging is T12, not a claim made by this stage.

## Proof and limits

The new MJS test fixture `tests/fixtures/ts-migration/caller.mjs` is deliberately untyped, only to prove legacy-to-compiled interoperation. It is never imported by production. The isolated canary and fixture are removed after T03 has equivalent actual-module coverage. New production type escapes: none.

The canary proves import identity and that the test and application run in the staged tree. Negative fixtures exercise the actual tsc CLI (nonzero with a bad call, zero after correction), excluded input, disabled strictness, unsafe output directories, missing resources, duplicate implementations, manifest/input/output tampering and failed-build invalidation. Tests mutate only their own full temporary clones; the original checkout remains untouched.

CI uses Node24 on Windows/Ubuntu plus isolated PG18 for the unchanged 17-file source baseline. The source result, shadow result and frozen-history result are separate. The existing current `--require-ready` failure must remain `KNOWN_BASELINE_NOT_READY`, not be described as PASS. Exact-head results and self/Codex review are attached to the PR; local diagnostics in `receipts/T01.json` are not remote acceptance.
